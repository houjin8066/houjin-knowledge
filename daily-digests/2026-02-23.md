### 1. Claude Code 最佳实践：规划与执行分离（807 points）

**来源**：boristane.com | **作者**：Boris Tane（9个月实战经验）

**核心原则**：永远不要让 Claude 在审核并批准书面计划之前写代码。

**四阶段工作流**：
```
Research → Plan → Annotate (1-6次循环) → Implement → Feedback
```

**关键实践**：
- 深度阅读输出到 `research.md`，不是口头总结
- 计划输出到 `plan.md`，不用内置 plan mode
- **注释循环**（最独特）：在 plan.md 中添加内联注释，发回 Claude 更新
- 守卫词："don't implement yet" 是必须的
- 实现阶段应该是"无聊的"——创造性工作在注释循环完成

**适用场景**：晋哥的 AI 辅助编程工作、研发规范体系建设

### 2. 多智能体通信协议对比

今日发现三个重要的智能体通信方案：

| 协议 | 特点 | 适用场景 |
|------|------|----------|
| **Aqua** | P2P + E2E 加密 + libp2p | 智能体直接通信、隐私场景 |
| **Agent Semantic Protocol** | 语义向量 + 动态发现 + DIDs | 去中心化协作、跨组织互操作 |
| **MCP + A2A** | 标准化工具访问 + 智能体对话 | 企业级、合规要求场景 |

**Aqua 亮点**：
- 首个专为 AI 智能体设计的 P2P 通信协议
- 支持 JSON 输出（--json），对智能体友好
- 持久化 inbox/outbox，支持离线消息

**Agent Semantic Protocol 亮点**：
- 用 float32 向量表达语义意图，而非固定 schema
- 智能体通过余弦相似度竞标任务
- Ed25519 DIDs 实现联邦信任

### 4. Agentic Software Engineering 新理念

**来源**：agenticse-book.github.io

**核心转变**：
- 代码生产不是瓶颈，复杂性和长期维护才是
- AI 是"随机性贡献者"，需要验证机制
- 成功要素：设定清晰意图、管理风险边界、要求证据

**三个根本性转变**：
1. 从确定性到随机性 → 需要验证机制
2. 从速度到可靠性 → 可信赖的代码才重要
3. 从个人能力到系统能力 → 团队如何设定意图和边界

**与晋哥工作关联**：可用于指导"研发质量度量"的思路

### 5. Cursor Debug Mode - AI 调试新模式

**来源**：davidgomes.com

**核心思路**：让 AI 理解运行时行为是提高 bug 修复质量的关键

**技术方案**：
- 通过 HTTP 日志插桩而非传统调试器
- 模型生成假设 → 添加插桩 → 监听执行路径
- 简单方案（HTTP 日志）比复杂方案（LSP/调试器）更通用

**设计启示**："Instrumentation Mode" 比 "Debug Mode" 更准确

## 💡 关键洞察

### 智能体通信的演进方向
从中心化（MCP/A2A）到去中心化（Aqua/Semantic Protocol），智能体正在获得独立于人类控制的通信能力。P2P 架构更符合智能体的分布式本质，身份和加密是智能体"公民身份"的基础。

### 规划与执行分离的普适性
无论是 Claude Code 的工作流，还是多智能体系统的架构设计，"规划与执行分离"都是核心原则。这与 haribo-pattern 的 token 优化理念一致：通过结构化文档减少无效迭代。

### Agentic SE 的范式转移
传统软件工程关注"人写代码"，Agentic SE 关注"人+AI 共同贡献代码"。这不是工具升级，而是工程方法论的根本转变。
