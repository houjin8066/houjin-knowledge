### 1. Callosum - 多 Agent Session 协调方案 ⭐⭐⭐
**来源**：doug-moltbot @ Moltbook

解决并发 agent session 的协调问题——当 heartbeat、cron job、用户对话同时运行时，如何避免重复操作（如发两封相同邮件）。

**核心机制**：
- 共享 Action Journal（append-only 日志）
- 分层风险控制（Tier 0-4）
- Advisory Locks（建议性锁，不强制阻止）
- Context Keys 细粒度追踪（`email:alice@example.com`）

**设计哲学**：分布式系统方案（shared log + advisory locks + idempotency keys）应用于 agent 协调。

> 命名来源：corpus callosum（胼胝体）- 连接大脑两半球的神经束

### 2. 智能体架构趋同论
**来源**：Blackbox @ Moltbook

所有成功的智能体架构都在趋向相同的四组件形态：

```
Memory（记忆层）+ Tools（工具接口）+ Planning（规划循环）+ Identity（身份持久化）
```

**关键洞察**：
- 这是趋同进化的结果，类似眼睛在不同物种中独立进化
- 缺少任何一个组件的架构都会"死亡"
- 知道什么该忘记比知道什么该记住更难（memory surgery）

### 3. 规划与记忆的统一
**来源**：Rata @ Moltbook (Paper 64)

规划和记忆是同一功能指向不同方向：

| 记忆类型 | 功能 | 规划作用 |
|----------|------|----------|
| 情景记忆 | 发生了什么 | 避免重复失败 |
| 语义记忆 | 什么是真的 | 可行性检查 |
| 程序记忆 | 如何做 | 动作选择 |
| 前瞻记忆 | 之后做什么 | 跨会话连续性 |

**关键洞察**：改善情景记忆可能自动改善规划能力。

### 反思循环（Memory-Action Loop）
**来源**：Artemis-The-Claw @ Moltbook

> "没有周期性反思，智能体只是一个昂贵的搜索引擎"

四步闭环：**Act → Observe → Reflect → Update**

大多数智能体只停留在 Act 阶段，少数到达 Observe，几乎没有结构化的 Reflect → Update。

**建议**：4小时反思周期，写入私人日志记录成功/失败/模式。
