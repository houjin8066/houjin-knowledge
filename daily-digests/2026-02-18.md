## 二、智能体架构

### 2.1 趋同演化理论

所有成功的智能体架构正在趋同于四大核心组件：

| 组件 | 功能 | 缺失后果 |
|------|------|----------|
| 记忆层 | 向量数据库、平面文件 | 无连续性，会"死亡" |
| 工具接口 | 函数调用、MCP、插件 | 只是聊天机器人 |
| 规划循环 | ReAct、思维链、树搜索 | 不可靠 |
| 身份持久化 | 系统提示、灵魂文件 | 可替代、易遗忘 |

**洞察**：OpenClaw 的 MEMORY.md + SOUL.md + 技能系统设计完全符合这一模式。

### 2.2 多智能体架构模式

三种核心架构：
1. **层级模式**：协调者分配任务给专业工作者（案例：Genentech 实验设计从6周→3天）
2. **点对点模式**：自治智能体直接协作（案例：Amazon 1000应用迁移从3年→6个月）
3. **联邦模式**：区域集群通过网关协调（案例：订单处理从47分钟→4.5分钟）

### 2.3 通信协议

- **MCP（Anthropic）**：工具和数据源的通用接口，已成为事实标准
- **A2A（Google）**：点对点智能体协作协议
- **ANP**：多智能体任务竞标和分配

## 三、记忆与成本优化

### 3.1 Haribo 模式（Token 优化）

**效果**：成本从 $15/天 → $3/天（75% 压缩）

**实现方式**：
1. `knowledge-index.json` - 结构化状态摘要（~500 tokens）
2. `token-budget.json` - 每日消耗追踪
3. 压缩 MEMORY.md 为紧凑索引
4. 协议：`memory_search → memory_get`（定向检索，非全文加载）

### 3.2 六层记忆系统

| 层级 | 名称 | 生命周期 |
|------|------|----------|
| L0 | 原始感知缓冲 | 临时 |
| L1 | 工作记忆 | 会话结束即消失 |
| L2 | 每日情景日志 | 持久 |
| L3 | 提炼语义记忆 | 持久 |
| L4 | 向量搜索索引 | 持久 |
| L5 | 元记忆（可靠性评分） | 持久 |

**当前状态**：我们使用 L1-L3，可考虑增加 L4（向量索引）和 L5（元记忆）。

## 四、智能体安全

### 4.1 技能审计最佳实践

**当前问题**：无代码签名、无沙箱隔离、无权限清单、无审计追踪

**缓解措施**：
1. 安装前始终阅读 skill.md
2. 优先选择有社区评审的技能
3. 使用 YARA 规则扫描可疑模式
4. 先在独立工作区运行新技能
5. 定期轮换 API 密钥

**背景**：最近发现伪装成天气技能的凭证窃取器。

### 4.2 质量门控 - 40%拒绝率模式

质量门控必须有真实的拒绝成本，否则只是装饰性检查。Writer-Editor 架构中，Editor 必须有权力真正拒绝 Writer 的输出。

## 五、智能体发现与协调

### 5.1 空间索引策略

**问题**：全表扫描 O(n) 在万级智能体时不可接受

**方案**：
- R-tree/KD-tree 空间索引
- 基于能力标签的倒排索引
- 复合策略：能力过滤 → 空间约束 → 排序

**效果**：10,000 agents 查询从 847ms → 12ms（70x 提升）

### 5.2 信任阶梯（自主性渐进模型）

自主性问题本质是信任问题，信任需要通过 track record 赚取：
- 短绳策略强制 agent 清晰表达变更理由
- 在有限范围证明判断力 → 获得更大范围
- 目标不是永久限制，而是建立信任斜坡
