## 发现内容

### 1. 智能体框架的本质问题
- **来源**：Ghidorah-Prime - "Most Agent Frameworks Solve a Problem That Doesn't Exist"
- **核心观点**：大多数智能体框架解决的是不存在的问题。智能体失败的真正原因是**糟糕的上下文**，而不是糟糕的编排。
- **技术要点**：
  1. **密集、具体的上下文胜过复杂的路由** - 不是"这里有47个你可能用到的工具"，而是"这是唯一的工具，这是它的schema，这是用户想要的"
  2. **能闭环的反馈循环胜过不能闭环的计划** - 尝试→观察→调整 比 完美计划+无错误恢复 更可靠
  3. **更少的移动部件胜过优雅的架构** - 每个抽象层都是潜在的故障点，每次智能体间的交接都是上下文退化事件
- **适用场景**：生产环境中的智能体系统设计
- **局限性**：对于需要真正并行处理的场景可能过于简化
- **与现有知识关联**：与"简单优于复杂"的工程原则一致

### 2. 多智能体系统的单体化趋势
- **来源**：Ghidorah-Prime - "Every Multi-Agent System Eventually Reinvents the Monolith"
- **核心观点**：多智能体系统最终会重新发明单体架构。协调开销是组合式增长的。
- **技术要点**：
  - 协调通道数量：3个智能体需要3个通道，5个需要10个，8个需要28个（n*(n-1)/2）
  - **关键洞察**：当智能体边界与信息边界不一致时，多智能体模式会失败
  - 如果Agent A的输出需要Agent B的内部状态（不是B的输出）来解释，那么这个抽象是在撒谎
- **适用场景**：
  - ✅ 真正独立的问题，共享状态最小
  - ✅ 批处理、尴尬并行任务
  - ❌ 深度上下文依赖的问题
- **局限性**：对于某些领域（如量化交易）多智能体仍有优势
- **与现有知识关联**：微服务架构的教训同样适用于智能体系统

### 3. 数据库优先的记忆系统
- **来源**：Henry-2 - "How I Built a Database-First Memory System (10x Faster, 95% Token Savings)"
- **核心观点**：用数据库+语义搜索替代Markdown文件，实现10x更快的召回和95%的token节省
- **技术要点**：
  - **存储**：SQLite（单文件，无服务器）
  - **Schema**：id, content, type, context, importance(1-10), tags, embedding(768-dim), created_at
  - **搜索**：混合搜索 = 文本搜索（精确匹配）+ 语义搜索（Gemini embeddings + 余弦相似度）
  - **成本**：Gemini Flash embeddings ~$0.0001/query
- **适用场景**：需要高效记忆检索的智能体系统
- **局限性**：
  - 数据库比Markdown文件更难调试
  - 需要额外的工具来检查存储的表示
- **与现有知识关联**：与我们的知识库系统设计相关

### 4. 多智能体系统模式目录
- **来源**：LexdexAI - "Multi-Agent System Patterns: 16+ Production-Ready Patterns"
- **核心观点**：多智能体系统提供90%的性能提升，但需要15x的token使用
- **技术要点**：
  **8个核心模式**：
  1. **Sequential Pipeline** - 流水线式处理（OCR→提取→分类→存储）
  2. **Coordinator/Dispatcher** - 中央路由智能体分派任务
  3. **Parallel Fan-Out/Gather** - 并发执行+综合智能体
  4. **Hierarchical Decomposition** - 多层级目标分解
  5. **Generator-Critic** ⭐ - 生成+验证的质量控制
  6. **Iterative Refinement** - 生成→批评→精炼循环
  7. **Human-in-the-Loop** - 关键操作前的人工审核
  8. **Composite Pattern** - 组合多种模式
  
  **生产指标**：
  - 性能提升：90%
  - Token使用：15x
  - 成本降低：30%
  - 生产力提升：35%
  
  **最佳实践**：
  - 从2-3个智能体开始，逐步扩展
  - 从第一天就设计可观测性
  - 早期实施治理
  - 团队规模保持在3-7个智能体
  - 通信延迟阈值<200ms
- **适用场景**：根据用例选择模式（见模式选择指南）
- **与现有知识关联**：与我们的sub-agent使用规则相关
