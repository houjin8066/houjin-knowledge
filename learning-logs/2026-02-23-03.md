### 1. Claude Code 工作流：规划与执行分离（807 points, 516 comments）

**来源**: https://boristane.com/blog/how-i-use-claude-code/
**作者**: Boris Tane

**核心观点**:
> "Never let Claude write code until you've reviewed and approved a written plan."

这是作者使用 Claude Code 9个月后总结的核心原则。规划与执行分离是最重要的实践，能防止浪费、保持架构控制、用更少的 token 产出更好的结果。

**四阶段工作流**:
```
Research → Plan → Annotate (1-6x) → Todo List → Implement → Feedback
```

**各阶段详解**:

1. **Research 阶段**
   - 深度阅读相关代码库
   - 输出到 `research.md`（不是口头总结）
   - 关键词："deeply", "in great details", "intricacies"
   - 目的：防止 Claude 浅读，确保真正理解系统

2. **Plan 阶段**
   - 输出到 `plan.md`（不用内置 plan mode）
   - 包含：详细说明、代码片段、文件路径、权衡考虑
   - 技巧：提供开源项目的参考实现

3. **Annotate 循环**（最独特的部分）
   - 在 plan.md 中添加内联注释
   - 注释类型：纠正假设、拒绝方案、添加约束、提供领域知识
   - 示例：
     - "use drizzle:generate for migrations, not raw SQL"
     - "no — this should be a PATCH, not a PUT"
     - "remove this section entirely"
   - 发送回 Claude："I added a few notes to the document, address all the notes and update the document accordingly. don't implement yet"
   - 重复 1-6 次
   - **关键守卫**: "don't implement yet"

4. **Todo List**
   - 实现前请求粒度任务分解
   - 作为进度追踪器

5. **Implement 阶段**
   - 标准提示词：
   ```
   implement it all. when you're done with a task or phase, mark it as completed 
   in the plan document. do not stop until all tasks and phases are completed. 
   do not add unnecessary comments or jsdocs, do not use any or unknown types. 
   continuously run typecheck to make sure you're not introducing new issues.
   ```
   - 实现应该是"无聊的"——创造性工作在注释循环中完成

6. **Feedback 阶段**
   - 简短修正："wider", "still cropped", "there's a 2px gap"
   - 引用现有代码作为参考
   - 出错时：revert + 缩小范围

**适用场景**:
- 复杂功能开发
- 需要与现有系统集成的任务
- 架构决策重要的场景

**局限性**:
- 简单任务可能过度工程化
- 需要开发者有足够的架构判断力
- 前期投入时间较多

**与现有知识关联**:
- 与 claude-code-agent-teams 技能中的"规划审批"模式一致
- 符合 haribo-pattern 的"按需检索"思想（plan.md 作为持久化上下文）
- 可整合到 memory-layers 的工作记忆层
