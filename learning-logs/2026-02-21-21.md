## 发现内容

### 1. Cord - 智能体树协调框架（重点）
- **来源**: https://www.june.kim/cord | HN 105 points
- **核心观点**: 让智能体自己构建任务树，而非开发者预定义工作流
- **技术要点**:
  - **Spawn vs Fork 原语**: spawn 创建干净上下文的子任务（像雇佣承包商），fork 继承所有兄弟结果（像团队成员汇报）
  - 5个核心工具: spawn(), fork(), ask(), complete(), read_tree()
  - 基于 Claude Code CLI + SQLite + MCP
  - ~500行 Python 实现
- **适用场景**: 复杂任务分解、需要并行执行和依赖管理的场景
- **局限性**: 依赖 Claude Code CLI，需要订阅
- **与现有知识关联**: 与 memory-layers 技能中的任务分解思想一致

### 2. 多智能体系统架构 2026 趋势
- **来源**: clickittech.com + dasroot.net
- **核心观点**: 
  - Gartner 报告 2024-2025 多智能体系统咨询量增长 1445%
  - 角色分离设计（Planner/Executor/Verifier/Optimizer）模仿人类团队结构
- **技术要点**:
  - 单智能体 vs 多智能体: 单点故障 vs 容错、浅层推理 vs 深度迭代
  - 通信协议: ACP (Agent Communication Protocol), MCP 2.1
  - 记忆架构: 分布式状态管理、共享记忆
- **适用场景**: 长周期推理、多步规划、工具编排、企业级工作流
- **局限性**: 协调开销、延迟增加、成本可能更高

### 3. LLM 推理失败分类框架
- **来源**: arXiv:2602.06176 (TMLR 2026)
- **核心观点**: 首个系统性 LLM 推理失败综述
- **技术要点**:
  - 推理类型: 具身推理 vs 非具身推理（直觉/逻辑）
  - 失败分类: 架构固有缺陷、领域特定限制、鲁棒性问题
  - GitHub 资源: https://github.com/Peiyang-Song/Awesome-LLM-Reasoning-Failures
- **与现有知识关联**: 设计智能体时需考虑这些失败模式
