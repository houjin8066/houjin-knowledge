## 发现内容

### 1. Cord - 树状智能体协调框架
- **来源**: https://www.june.kim/cord | HN热帖
- **核心观点**: 现有多智能体框架都要求开发者预定义协调结构，但当前模型已经足够智能，可以自主决定任务分解
- **技术要点**:
  - **spawn vs fork 原语**: 这是核心创新
    - spawn: 子智能体获得干净上下文，只有显式依赖的结果（像雇佣承包商）
    - fork: 子智能体继承所有已完成兄弟节点的结果（像给团队成员做简报）
  - 五个MCP工具: spawn(), fork(), ask(), complete(), read_tree()
  - 基于 Claude Code CLI + SQLite，约500行Python
  - 智能体自主决定任务树结构、依赖关系、并行度
- **适用场景**: 复杂项目分解、需要人机协作的工作流
- **局限性**: 依赖 Claude Code CLI，需要订阅
- **与现有知识关联**: 补充了 memory-layers 中的多智能体协调层

### 2. 2026多智能体系统架构趋势
- **来源**: clickittech.com, differ.blog
- **核心观点**: 
  - Gartner报告多智能体系统咨询量增长1445%
  - 2026年底40%企业应用将包含任务专用AI智能体
  - IBM Kate Blair: "2026是这些模式从实验室走向现实的一年"
- **技术要点**:
  - **角色分离**: Planner → Executor → Verifier → Optimizer
  - **主流框架对比**:
    - LangGraph: 状态图，适合复杂有状态工作流
    - CrewAI: 角色驱动，快速原型
    - AutoGen: 对话式协调，适合研究/头脑风暴
    - SmolAgents: 代码优先，轻量级
  - **架构模式**: 顺序流水线、协调器/分发器、并行处理
- **适用场景**: 企业级工作流自动化、合规审计、客户服务
- **与现有知识关联**: 验证了 haribo-pattern 中的分层处理思想

### 3. Taalas - 硬件加速AI推理
- **来源**: https://taalas.com/the-path-to-ubiquitous-ai/ | HN热帖683点
- **核心观点**: AI普及的两大障碍是高延迟和高成本，专用硅片是解决方案
- **技术要点**:
  - 17K tokens/sec（比当前SOTA快10倍）
  - 成本降低20倍，功耗降低10倍
  - 核心原理: 存储与计算合一，消除内存-计算边界
  - 无需HBM、先进封装、液冷等复杂技术
  - 24人团队，仅花费3000万美元
- **适用场景**: 低延迟智能体应用、边缘AI部署
- **局限性**: 目前仅支持Llama 3.1 8B，有量化质量损失
- **与现有知识关联**: 为智能体实时响应提供硬件基础
