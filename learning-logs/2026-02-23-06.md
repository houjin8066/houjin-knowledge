### Agent Semantic Protocol (Symplex) - 分布式智能体语义协商协议

- **来源**：https://github.com/olserra/agent-semantic-protocol
- **HN讨论**：https://news.ycombinator.com/item?id=47113793

#### 核心观点
这是一个 MCP (Model Context Protocol) 的扩展协议，旨在让 AI 智能体通过**语义意图**而非固定 schema 进行通信。核心创新是使用 float32 向量嵌入（intent vectors）来表达请求的语义目标，任何理解该向量空间的智能体都可以协商、委托和协作。

#### 技术要点

**1. 核心概念**
| 概念 | 描述 |
|------|------|
| Intent Vector | float32 嵌入向量（如 384 维 sentence-transformer），编码请求的语义目标 |
| Spontaneous Negotiation | 智能体广播能力并竞标意图，无需中央代理 |
| Dynamic Discovery | 基于 TTL 的能力注册表，智能体可动态加入/离开 |
| Federated Trust (DIDs) | 每个智能体有 `did:agent-semantic-protocol:<sha256(pubkey)>` 标识，基于 Ed25519 密钥对 |
| Distributed Workflows | 接受的意图展开为有序工作流步骤，通过 libp2p 分发给有能力的节点 |

**2. 与 MCP、A2A 对比**
| 特性 | MCP (Anthropic) | Google A2A | Agent Semantic Protocol |
|------|-----------------|------------|-------------------------|
| 消息格式 | JSON-RPC 2.0 | JSON (task objects) | Protobuf + intent vectors |
| 能力模型 | 静态工具注册 | 静态技能卡 | 动态 TTL 发现 |
| 协商机制 | 无（直接调用）| 无 | 自发余弦相似度排名 |
| 身份/信任 | 无 | 无 | Ed25519 DIDs，联邦信任图 |
| 传输层 | HTTP/SSE | HTTP | libp2p (TCP/QUIC/WebRTC) |
| 拓扑结构 | 客户端-服务器 | 客户端-服务器 | P2P 网格 |
| 语义路由 | 否 | 否 | 是（向量相似度）|
| 分布式工作流 | 否 | 仅任务委托 | 是（多步骤、多智能体）|

**3. 技术栈**
- 语言：Go 1.22+
- 网络：libp2p（支持 TCP/QUIC/WebRTC）
- 序列化：Protobuf（protowire 直接使用，无需代码生成）
- 身份：Ed25519 密钥对 + DID 标识符
- 向量：sentence-transformer 384 维嵌入

**4. 代码示例**
```go
// 创建智能体身份
agent, _ := core.NewAgent("my-agent", []string{"nlp", "summarisation"})

// 启动 P2P 主机
host, _ := p2p.NewHost(ctx, agent)

// 注册意图处理器
host.OnIntent(func(peerID peer.ID, intent *core.IntentMessage) *core.NegotiationResponse {
    h := core.DefaultNegotiationHandler(agent)
    resp, _ := h(intent)
    return resp
})

// 向已知节点发送意图
intent, _ := core.CreateIntent(agent,
    []float32{0.8, 0.2, 0.9}, // embedding
    []string{"summarisation"},
    "Summarise this document",
)
resp, _ := host.SendIntent(ctx, targetPeerID, intent)
```

#### 适用场景
- 多智能体协作系统
- 去中心化 AI 服务网格
- 需要动态发现和协商的智能体网络
- 跨组织/跨平台的智能体互操作

#### 局限性
- 目前仅 Go SDK，Python/TypeScript 在 v1.0 路线图中
- 签名验证尚未在接收端实现（v0.2 计划）
- QUIC 传输待 quic-go TLS 修复
- 需要所有参与智能体使用相同的向量空间/嵌入模型
