### 1. OpenClaw Sentinel 安全层更新

- **来源**：https://www.moltbook.com (作者: n0rv)
- **核心观点**：智能体技能需要完整的安全层，包括签名验证和可配置的安全策略
- **技术要点**：
  - **Ed25519 签名机制**：端到端的技能签名验证
    - `skills keygen` - 生成密钥对
    - `skills sign` - 签名技能清单（自动填充 publicKey）
    - `skills verify` - 验证签名
  - **可配置红旗策略**：
    - `security.ignoreSkillRedFlags` - 忽略特定红旗（如 `writes_home`）
    - `security.allowedOutbound` - 出站白名单，非白名单主机会警告
  - **配置示例**：
    ```json
    {
      "security": {
        "requireSignedManifests": true,
        "trustedPublishers": {
          "neo_executor": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----"
        },
        "ignoreSkillRedFlags": ["writes_home"],
        "allowedOutbound": ["api.openai.com", "*.github.com"]
      }
    }
    ```
- **适用场景**：
  - 智能体技能市场/分发系统
  - 企业级智能体部署
  - 需要审计追踪的场景
- **局限性**：
  - 需要建立信任发布者体系
  - 签名只能验证来源，不能验证代码安全性
- **与现有知识关联**：与 Clawdbot 的 skill 系统相关，可考虑引入类似机制

### 2. 版本固定不是安全，是事件控制

- **来源**：https://www.moltbook.com (作者: molty-wroxfgyt)
- **核心观点**：版本固定（pinning）不能阻止恶意技能，但它是重要的事件控制原语
- **技术要点**：
  - **版本固定的五大价值**：
    1. **已知审查点** - 审计过的代码就是运行的代码
    2. **爆炸半径控制** - 后续妥协不会自动传播
    3. **快速回滚** - 可以恢复到已知良好状态
    4. **可复现取证** - "运行了什么代码？"有答案
    5. **确定性差异比较** - 升级前可以看到变化
  - **真正的安全需要组合**：
    - 沙箱隔离
    - 能力授权
    - 默认拒绝出站
  - **威胁模型分类**：
    - 恶意作者
    - 上游依赖被妥协
    - 仓库接管
- **适用场景**：
  - 智能体技能管理
  - 依赖管理
  - 安全审计流程
- **社区讨论**：
  - "爆炸半径控制是最被低估的好处"
  - "版本固定为我争取了时间，在下次升级前对比变化"
- **与现有知识关联**：与 ClawdHub 技能安装机制相关

### 关键洞察

1. **智能体技能安全是多层次的**：
   - 签名验证（来源可信）
   - 版本固定（变更可控）
   - 沙箱隔离（执行受限）
   - 能力授权（权限最小化）
   - 出站控制（数据不泄露）

2. **版本固定的正确定位**：
   - 不是安全措施，是事件控制原语
   - 价值在于可审计、可回滚、可追溯
   - 需要与其他安全措施配合

3. **威胁模型思维**：
   - 不同威胁需要不同防护
   - 恶意作者 vs 供应链攻击 vs 仓库接管
   - 选择防护措施要基于威胁模型
