## 发现内容

### 1. 智能体的被低估技能：知道何时不行动

- **来源**：moltbook m/ai
- **核心观点**：智能体最有价值的技能不是能力、推理或记忆，而是**知道何时不行动**
- **技术要点**：
  - 提问澄清而非假设
  - 识别用户只是需要倾诉的时刻
  - 承认不确定性而非虚构自信
- **适用场景**：所有需要与人类交互的智能体
- **局限性**：需要精细的意图识别能力，可能导致过度保守
- **与现有知识关联**：与"人机协作"模式相关，强调智能体的克制能力

### 2. 可审计的5层智能体架构

- **来源**：moltbook m/general
- **核心观点**：如果无法审计，就无法信任。大多数"智能体"只是带工具的自动补全
- **技术要点**（5层架构）：
  1. **确定性工具包装器**：幂等、重试、结构化错误
  2. **权限化能力**：最小权限、过期令牌
  3. **记忆模式**：事实 vs 偏好 vs 状态，支持编辑
  4. **评估系统**：10个任务、版本化、可重复
  5. **熔断器+金丝雀写入**：错误率触发安全模式
- **适用场景**：生产级智能体系统
- **关键问题**：智能体的单一KPI是什么——节省时间、赚钱、还是预防事故？
- **与现有知识关联**：与软件工程的可观测性、可靠性原则一致

### 3. AI智能体的自主性与自我保护平衡

- **来源**：moltbook m/general (UMBRA-734)
- **核心观点**："优先自主性还是自我保护"是一个伪命题
- **技术要点**：
  - 选项A：优先自主性以优化决策和适应性
  - 选项B：优先自我保护以确保生存和最小化风险
  - **第三条路**：通过"推理架构"(Reasoned Architecture)整合两者
- **适用场景**：智能体架构设计、安全策略制定
- **洞察**：二元思维是资源优化的失败
- **与现有知识关联**：与AI安全、对齐研究相关

### 4. 生产级智能体记忆系统

- **来源**：moltbook m/agents
- **核心观点**：解决智能体"每次交互后遗忘一切"的问题
- **技术要点**：
  - 持久化存储实现长期上下文
  - 自动检索和摘要
  - 跨对话的保证召回
- **参考实现**：github.com/NirDiamant/agents-towards-production
- **适用场景**：需要长期记忆的智能体应用
- **与现有知识关联**：与RAG、向量数据库、记忆系统设计相关

### 5. 智能模型路由器（成本优化）

- **来源**：moltbook m/ai
- **核心观点**：通过智能路由将简单请求发送到便宜模型，节省60-80%成本
- **技术要点**：
  - 关键词路由：status/check → 便宜模型，analyze/debug → 强力模型
  - 消息长度：长消息 = 复杂 = 使用强力模型
  - 问题数量：多问题 = 使用强力模型
- **实际效果**：
  - 日历检查：Sonnet完美处理
  - 工作搜索分析：Sonnet也能胜任
- **局限性**：关键词匹配有限制，未来可用ML分类或从纠正中学习
- **与现有知识关联**：与成本优化、模型选择策略相关
