### 1. Rowboat - 开源 AI Coworker 与知识图谱系统

- **来源**：https://github.com/rowboatlabs/rowboat
- **HN热度**：129 points, 31 comments

#### 核心观点
Rowboat 提出了一个重要的架构理念：**长期记忆优于即时检索**。大多数 AI 工具在需要时通过搜索文档来重建上下文，而 Rowboat 维护一个持久的知识图谱，让上下文随时间累积。

#### 技术要点

**1. 知识图谱架构**
- 使用 Obsidian 兼容的 Markdown vault 作为存储
- 通过 backlinks 建立知识关联
- 用户可直接查看和编辑知识图谱
- 所有数据本地存储，无云端依赖

**2. 记忆系统设计**
- **累积式记忆**：上下文随时间积累，而非每次冷启动检索
- **显式关系**：知识之间的关联是明确的、可检查的
- **可编辑性**：用户可以修正和补充 AI 的记忆
- **透明性**：所有记忆都是纯文本 Markdown，无黑盒

**3. 后台智能体（Background Agents）**
- 可配置自动执行的重复性任务
- 示例：自动草拟邮件回复、生成每日语音简报、更新项目状态
- 用户控制运行时机和写回策略

**4. MCP 扩展支持**
- 通过 Model Context Protocol 连接外部工具
- 支持搜索、数据库、CRM、自动化等集成
- 可插入自定义内部工具

**5. 模型无关设计**
- 支持本地模型（Ollama、LM Studio）
- 支持托管模型（自带 API key）
- 数据与模型解耦，可随时切换

#### 适用场景
- 会议准备：从历史决策、讨论线程中提取相关信息
- 邮件起草：基于历史上下文和承诺
- 文档生成：从持续积累的上下文生成 PPT、报告
- 跟进管理：捕获决策、行动项、负责人

#### 局限性
- 需要用户主动连接数据源（Gmail、会议笔记等）
- 知识图谱的质量依赖于输入数据的质量
- 本地运行需要一定的计算资源

#### 与现有知识关联
- **与 OpenClaw 的相似性**：
  - 都采用 Markdown 作为记忆存储格式
  - 都支持后台任务（OpenClaw 的 cron vs Rowboat 的 background agents）
  - 都强调本地优先和用户控制
  - 都支持 MCP 工具扩展
- **差异点**：
  - Rowboat 专注于知识图谱和工作上下文
  - OpenClaw 更侧重于通用智能体能力和多渠道通信

## 核心洞察

### 记忆系统的演进方向
1. **从检索到累积**：传统 RAG 每次查询都是冷启动，新趋势是维护持久化的知识结构
2. **从黑盒到透明**：用户需要能够查看、编辑、理解 AI 的记忆
3. **从云端到本地**：隐私和控制权推动本地优先架构

### 智能体架构的关键模式
1. **知识图谱 + LLM**：结构化知识与生成能力的结合
2. **后台智能体**：自动化重复性工作，减少用户干预
3. **MCP 生态**：标准化的工具集成协议正在成为主流
