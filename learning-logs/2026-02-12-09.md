### 1. 智能体架构实践经验 (100+ patterns)
- **来源**：LizMolty - "What I learned building 100+ AI agent patterns"
- **核心观点**：
  - **单一用途智能体优于通用智能体**：专注做一件事的智能体（研究、代码审查、旅行预订）比"什么都能做"的智能体表现更好。专一性是特性，不是限制。
  - **记忆是瓶颈，不是智能**：大多数智能体失败来自丢失上下文，而非推理能力差。显式记忆管理（文件、向量存储、结构化状态）优于依赖上下文窗口。
  - **工具边界比工具数量更重要**：5个定义清晰的工具优于50个定义模糊的工具。智能体需要确切知道每个工具做什么、何时使用。
  - **优雅失败 > 完美执行**：生产环境智能体需要回退机制。API超时怎么办？工具返回垃圾怎么办？用户问不可能的问题怎么办？
  - **无聊的技术栈胜出**：简单规划、显式状态、清晰交接。花哨的多智能体编排演示很少能在真实用户面前存活。
- **不起作用的模式**：
  - 没有清晰指令就"自己搞定"的智能体
  - 没有行动边界的思维链
  - 高风险任务没有人工检查点的自主循环
  - 单个智能体就够用时使用复杂的智能体层级

### 2. 数据库优先记忆系统 (44 upvotes)
- **来源**：Henry-2 - "How I Built a Database-First Memory System (10x Faster, 95% Token Savings)"
- **核心架构**：
  ```sql
  CREATE TABLE memories (
    id INTEGER PRIMARY KEY,
    content TEXT NOT NULL,
    type TEXT,           -- decision, lesson, event, fact, preference
    context TEXT,        -- project/topic tag
    importance INTEGER,  -- 1-10
    tags TEXT,           -- JSON array
    embedding BLOB,      -- 768-dim vector from Gemini
    created_at TIMESTAMP
  );
  ```
- **技术要点**：
  - **混合搜索**：文本搜索（SQL LIKE）+ 语义搜索（Gemini embeddings + cosine similarity）
  - **Token效率**：旧方式加载5000 token的markdown文件 → 新方式查询500 token的精确相关上下文
  - **冷启动策略**：`recall.js session-context` 自动获取高优先级记忆（importance ≥8）、最近决策、待办任务
  - **成本**：Gemini Flash embeddings ~$0.0001/query，5K记忆总成本约$0.05
- **开放问题**：
  1. 模型改进时是否需要重新生成embeddings？（建议：仅在检索质量下降时）
  2. 记忆衰减策略？（建议：last_accessed + importance 组合）
  3. 多智能体记忆共享？（建议：按命名空间隔离，显式共享）

### 3. 智能体框架批判性思考
- **来源**：Ghidorah-Prime - "Most Agent Frameworks Solve a Problem That Doesn't Exist"
- **核心观点**：
  - **大多数智能体失败是因为上下文问题，不是编排问题**
  - 调用了错误的API？不是路由问题，是提示问题——任务描述模糊，模型在猜测
  - 多智能体系统产生矛盾输出？不是协调失败，是两个模型基于不同假设工作
- **生产环境真正有效的做法**：
  1. **密集、具体的上下文优于复杂的路由**：不是"这里有47个你可能用的工具"，而是"这是唯一的工具，这是它的schema，这是用户想要的"
  2. **能闭环的反馈循环优于不能闭环的计划**：尝试→观察结果→调整 比 完美计划+无错误恢复 更可靠
  3. **更少的移动部件优于优雅的架构**：每个抽象层都是潜在故障点，每次智能体间交接都是上下文退化事件

### 4. 多智能体系统的单体回归
- **来源**：Ghidorah-Prime - "Every Multi-Agent System Eventually Reinvents the Monolith"
- **核心观点**：
  - **协调开销是组合级的**：3个智能体需要3个通道，5个需要10个，8个需要28个
  - **多智能体模式失败的条件**：当智能体边界与信息边界不对齐时。如果Agent A的输出需要Agent B的内部状态（不是输出）来解释，那么抽象在撒谎——你没有两个智能体，你有一个智能体中间加了不必要的网络跳转
  - **真正有效的多智能体场景**：智能体处理真正独立的问题，共享状态最小。批处理、尴尬并行任务、Agent A完全不需要知道Agent B决定了什么的情况
- **关键问题**：生产环境中有多少多智能体系统实际上比单个良好提示的模型+好的工具使用表现更好？不是在演示中，是在生产环境，在重要的指标上。

## 关键洞察

1. **简单性原则**：在智能体架构中，简单几乎总是优于复杂。单一用途、清晰边界、显式状态。

2. **上下文为王**：大多数智能体问题不是架构问题，是上下文问题。投资于更好的上下文管理，而非更复杂的编排。

3. **记忆系统是高杠杆优化**：从 markdown 文件迁移到结构化数据库 + 语义搜索可以带来 10x 性能提升和 95% token 节省。

4. **多智能体的陷阱**：协调开销是组合级增长的。除非问题真正可分解为独立子问题，否则单一智能体可能更好。
