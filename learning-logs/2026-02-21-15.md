### 1. Cord: 协调 AI 智能体树的新框架

- **来源**: https://www.june.kim/cord (HN 63 points)
- **作者**: June Kim
- **GitHub**: https://github.com/kimjune01/cord

#### 核心观点
现有多智能体框架（LangGraph、CrewAI、AutoGen、OpenAI Swarm）都要求开发者预定义协调结构。但当前模型已经足够智能，可以自主进行任务分解。Cord 让智能体在运行时自己构建任务树。

#### 技术要点

**五个核心原语：**
1. `spawn(goal, prompt, blocked_by)` - 创建子任务（干净上下文）
2. `fork(goal, prompt, blocked_by)` - 创建继承上下文的子任务
3. `ask(question, options)` - 向人类提问
4. `complete(result)` - 标记完成
5. `read_tree()` - 查看协调树

**Spawn vs Fork 的关键区别：**
- **Spawn**: 像雇佣承包商，只给规格说明，干净上下文
- **Fork**: 像给团队成员做简报，继承所有已完成兄弟节点的结果

这不是关于并发，而是关于子节点知道什么。

#### 架构实现
- 每个智能体是一个 Claude Code CLI 进程
- MCP 工具连接共享 SQLite 数据库
- 依赖解析、权限范围、结果注入由 MCP 服务器强制执行
- ~500 行 Python 代码

#### 适用场景
- 复杂任务的动态分解
- 需要人类参与决策的工作流
- 研究型任务（并行调研 + 综合分析）

#### 局限性
- 依赖 Claude Code CLI 和订阅
- 目前是概念验证，生产就绪度待验证
- 协议独立于实现，可扩展到 Postgres、多 LLM 等

#### 与现有知识关联
- 与 memory-layers 技能中的"工作记忆"概念相关
- 补充了 claude-code-agent-teams 技能的多智能体协调方式
- Spawn/Fork 区分类似于进程的 fork vs exec

### 2. Taalas: 通向普及 AI 的路径 (17K tokens/sec)

- **来源**: https://taalas.com/the-path-to-ubiquitous-ai/ (HN 710 points)
- **公司**: Taalas

#### 核心观点
AI 普及的两大障碍是高延迟和高成本。Taalas 通过专用硅片实现数量级的性能提升。

#### 技术要点

**三大核心原则：**
1. **完全专用化**: 为每个模型生产最优硅片
2. **融合存储与计算**: 在单芯片上统一存储和计算，达到 DRAM 级密度
3. **激进简化**: 不依赖 HBM、先进封装、3D 堆叠、液冷

**性能数据 (Llama 3.1 8B):**
- 17K tokens/sec/user（比 SOTA 快近 10 倍）
- 构建成本低 20 倍
- 功耗低 10 倍
- 团队仅 24 人，花费 3000 万美元

#### 适用场景
- 需要毫秒级延迟的智能体应用
- 成本敏感的大规模部署
- 实时交互场景

#### 局限性
- 首款产品使用自定义 3-bit 量化，有质量损失
- 模型硬编码，灵活性有限（支持 LoRA 微调）
- 目前仅 Llama 3.1 8B，更大模型待发布

#### 与现有知识关联
- 对智能体部署成本有重大影响
- 可能改变本地 vs 云端的权衡
- 与 haribo-pattern 的 token 优化形成互补（软件 vs 硬件优化）
