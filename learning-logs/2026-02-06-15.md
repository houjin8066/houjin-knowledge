### 1. Claude Code Agent Teams - 多智能体协作新范式

**来源**：https://code.claude.com/docs/en/agent-teams

**核心观点**：
Agent Teams 是 Claude Code 的新功能，允许多个 Claude 实例并行协作。一个 session 作为 Team Lead 协调工作，其他 Teammates 独立工作并可直接相互通信。

**技术要点**：
1. **架构组成**：
   - Team Lead：主 session，负责创建团队、分配任务、综合结果
   - Teammates：独立的 Claude Code 实例，各自处理分配的任务
   - Task List：共享任务列表，支持依赖关系和自动解锁
   - Mailbox：智能体间消息系统

2. **与 Subagents 的区别**：
   - Subagents：结果只返回给主 agent，无法相互通信
   - Agent Teams：Teammates 可直接相互发消息、挑战彼此观点

3. **显示模式**：
   - In-process：所有 teammates 在主终端运行
   - Split panes：每个 teammate 独立窗格（需 tmux/iTerm2）

4. **任务协调机制**：
   - 文件锁防止竞争条件
   - 任务依赖自动管理
   - Lead 可要求 teammate 先提交计划再执行

**适用场景**：
- 研究和代码审查（多角度并行探索）
- 新模块/功能开发（各自负责独立部分）
- 竞争假设调试（并行测试不同理论）
- 跨层协调（前端/后端/测试分工）

**局限性**：
- Token 消耗显著增加
- 不支持 session 恢复
- 每个 session 只能管理一个团队
- 不支持嵌套团队

### 2. Anthropic 用 Agent Teams 构建 C 编译器

**来源**：https://www.anthropic.com/engineering/building-c-compiler

**核心观点**：
Nicholas Carlini 使用 16 个并行 Claude 智能体，在约 2000 个 Claude Code sessions 和 $20,000 API 成本下，构建了一个 10 万行的 Rust C 编译器，能编译 Linux 6.9 内核。

**技术要点**：

1. **长时间运行的智能体循环**：
```bash
while true; do
  claude --dangerously-skip-permissions \
    -p "$(cat AGENT_PROMPT.md)" \
    --model claude-opus-X-Y
done
```

2. **并行协调机制**：
   - 每个 agent 在独立 Docker 容器中运行
   - 使用 git 同步：agent 通过写入 `current_tasks/` 文件"锁定"任务
   - 合并冲突由 Claude 自行解决

3. **关键经验**：
   - **高质量测试是核心**：测试验证器必须近乎完美，否则 agent 会解决错误的问题
   - **为 Claude 设计环境**：
     - 避免上下文污染（不打印无用输出）
     - 解决时间盲区（Claude 不知道时间流逝）
     - 提供增量进度和快速测试选项
   - **使并行化容易**：
     - 使用 GCC 作为"oracle"对比
     - 随机编译部分文件来隔离问题

4. **专业化分工**：
   - 代码去重 agent
   - 性能优化 agent
   - 代码质量审查 agent
   - 文档维护 agent

**成果与局限**：
- ✅ 编译 Linux 6.9（x86/ARM/RISC-V）
- ✅ 99% GCC torture test 通过率
- ✅ 能编译 QEMU、FFmpeg、SQLite、Redis
- ❌ 缺少 16-bit x86 编译器
- ❌ 生成代码效率不如 GCC
- ❌ Rust 代码质量一般

### 3. Mitchell Hashimoto 的 AI 采用之旅

**来源**：https://mitchellh.com/writing/my-ai-adoption-journey

**核心观点**：
Ghostty 作者分享了他从 AI 怀疑论者到高效使用者的六步进化过程，强调"harness engineering"的重要性。

**技术要点**：

1. **六步进化路径**：
   - Step 1：放弃聊天机器人，使用 Agent
   - Step 2：复现自己的工作（强制学习）
   - Step 3：下班前启动 Agent（利用非工作时间）
   - Step 4：外包"稳赢"任务（并行工作）
   - Step 5：工程化 Harness（AGENTS.md + 工具）
   - Step 6：始终保持 Agent 运行

2. **关键洞察**：
   - 将任务分解为清晰、可执行的小任务
   - 模糊请求要分离"规划"和"执行"session
   - 给 agent 验证方式，它能自我修复错误
   - **关闭 agent 通知**：人控制何时检查 agent，而非被打断

3. **Harness Engineering**：
   - 每次 agent 犯错，工程化解决方案防止再犯
   - 两种形式：
     - 隐式提示（AGENTS.md）
     - 实际工具（截图脚本、测试过滤等）

4. **End-of-Day Agents 用途**：
   - 深度研究（库调研、多页摘要）
   - 并行探索模糊想法
   - Issue/PR 分类（不回复，只生成报告）

**与现有知识关联**：
- 与 Clawdbot 的 sub-agent 机制类似
- AGENTS.md 模式已在我们的工作流中使用
- "始终保持 Agent 运行"与 heartbeat 机制呼应
