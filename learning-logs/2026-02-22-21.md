### 1. Claude Code 规划与执行分离方法 🔥（HN 643 points）
- **来源**: https://boristane.com/blog/how-i-use-claude-code/
- **核心观点**: 永远不要让 Claude 在你审核并批准书面计划之前写代码
- **工作流**: Research → Plan → Annotate (1-6轮) → Todo List → Implement → Feedback
- **关键技术**:
  - 深度阅读指令：使用 "deeply", "in great details", "intricacies" 等词
  - 持久化 markdown 文件作为共享可变状态
  - 注释循环：在 plan.md 中直接添加内联注释，让 Claude 更新
  - "don't implement yet" 守卫防止过早执行
- **适用场景**: 复杂功能开发、需要架构决策的任务
- **局限性**: 需要人工深度参与，不适合简单任务
- **与现有知识关联**: 与 haribo-pattern 的分层思想一致，规划阶段是"压缩"决策的过程

### 2. 2026 多智能体系统架构指南
- **来源**: https://differ.blog/p/how-to-build-multi-agent-systems-complete-2026-guide-f50e02
- **核心观点**: 
  - AI 智能体市场从 2025 年 76.3 亿美元增长到 2033 年预计 1829.7 亿美元（49.6% CAGR）
  - 2026 年是多智能体系统从实验室走向生产的关键年
  - 到 2026 年底，40% 企业应用将包含任务特定 AI 智能体
- **三大架构模式**:
  1. Sequential Pipeline（顺序流水线）- 适合清晰交接的工作流
  2. Coordinator/Dispatcher（协调器/调度器）- 适合分诊系统
  3. Parallel Processing（并行处理）- 适合速度优先且任务独立的场景
- **8大框架对比**:
  | 框架 | 最佳场景 | 特点 |
  |------|----------|------|
  | LangGraph | 复杂有状态工作流 | 状态图、可回溯、人工审批 |
  | CrewAI | 角色协作 | 高层抽象、快速原型 |
  | AutoGen | 对话式多智能体 | 事件驱动、异步协作 |
  | LangChain | 文档处理 | 生态丰富、RAG 集成 |
  | AgentFlow | 企业合规 | 审计追踪、置信度评分 |
  | Atomic Agents | 分布式系统 | 真正分布式、跨区域 |
  | SmolAgents | 代码优先 | 轻量、写代码而非 JSON |
  | Langflow | 低代码 | 拖拽界面、快速原型 |

### 3. Human Root of Trust - 智能体问责框架
- **来源**: https://humanrootoftrust.org/
- **核心原则**: "Every agent must trace to a human"（每个智能体必须追溯到人类）
- **问题背景**: 
  - 商业互联网的隐含假设是另一端有人类
  - AI 智能体现在可以自主浏览、交易、通信、协调
  - 没人知道哪个人类对智能体的行为负责
- **架构**: 六步信任链（Trust Chain）
- **意义**: 为监管、审计、问责提供框架基础
- **与现有知识关联**: 与 memory-layers 的"人类监督"层相呼应

### 4. Stripe Minions - 一次性端到端编码智能体
- **来源**: https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents
- **核心观点**: Stripe 内部编码智能体，每周合并超过 1000 个 PR
- **特点**: 人类审核代码，但 minions 从头到尾编写
- **意义**: 大规模生产环境中智能体编码的成功案例
