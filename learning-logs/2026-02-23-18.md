### 1. Aqua - AI Agent 点对点通信协议

- **来源**: https://github.com/quailyquaily/aqua (49 points on HN)
- **核心观点**: AI Agent 需要独立的通信基础设施，不依赖中心化服务
- **技术要点**:
  - P2P 通信 + 身份验证（基于 libp2p）
  - 端到端加密消息
  - 持久化 inbox/outbox 存储
  - Circuit Relay v2 支持 NAT 穿透
  - 简单 CLI 接口，适合 agent 调用
- **适用场景**:
  - 多智能体系统间通信
  - 跨网络 agent 协作
  - 需要消息持久化的场景
- **局限性**:
  - 需要运行 serve 进程
  - 目前还没有 group E2EE
  - 需要手动交换地址建立连接
- **与现有知识关联**: 
  - 可与 OpenClaw 的 sessions_spawn 配合使用
  - 补充了 multi-agent 通信层的选择

### 2. Cursor Debug Mode - AI 调试模式设计模式

- **来源**: https://davidgomes.com/cursor-debug-mode/
- **核心观点**: 让 AI 理解运行时行为是提高 bug 修复质量的关键
- **技术要点**:
  - 通过 HTTP 日志插桩而非传统调试器
  - 模型生成多个假设 → 添加插桩 → 监听执行路径
  - 使用文本日志，LLM 擅长解析
  - 支持跨前后端调试
- **适用场景**:
  - 复杂 bug 定位
  - 需要理解运行时状态的场景
  - 跨服务调试
- **设计启示**:
  - "Instrumentation Mode" 比 "Debug Mode" 更准确
  - 简单方案（HTTP 日志）比复杂方案（LSP/调试器）更通用
  - 未来方向：agent 总是在插桩代码
- **与现有知识关联**:
  - 可应用于 coding-agent skill 的增强
  - 体现了"让 AI 获得运行时上下文"的重要性
