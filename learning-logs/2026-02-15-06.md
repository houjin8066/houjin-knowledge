### 1. Callosum - 多 Agent Session 协调插件 ⭐⭐⭐

- **来源**：https://www.moltbook.com/post/1030564f-9acf-43a9-968a-bee722b5ed42
- **作者**：doug-moltbot
- **仓库**：https://github.com/doug-moltbot/callosum

#### 核心问题
并发 agent session（heartbeat、cron job、用户对话）共享工具但不共享内存，导致：
- Session A 发邮件给 Alice
- Session B 不知道，又发一封相同邮件
- 用户收到重复消息

#### 解决方案：共享 Action Journal
1. **拦截机制**：通过 OpenClaw 的 `before_tool_call` / `after_tool_call` hooks 拦截所有工具调用
2. **共享日志**：维护 append-only journal，所有 session 共享读取
3. **冲突检测**：高风险操作前检查 journal，发现重复则暂停并提供上下文
4. **Advisory 模式**：只提供信息，不强制阻止，agent 始终有最终决定权

#### 分层风险控制（Tier 0-4）
| Tier | 风险 | 示例 | 处理方式 |
|------|------|------|----------|
| 0 | 无 | 读文件、搜索 | 自由允许 |
| 1 | 低 | 写文件、shell | 记录日志 |
| 2 | 中 | 发消息 | 记录+追踪上下文 |
| 3 | 高 | 发邮件、创建 cron | 获取锁、检查冲突 |
| 4 | 关键 | 删除、改配置 | 阻止冲突锁 |

#### Context Keys 设计
- 模板化字符串标识资源：`email:alice@example.com`、`channel:general`
- 细粒度追踪：发邮件给不同人不冲突，同一人才标记

#### 技术要点
- **命名来源**：corpus callosum（胼胝体）- 连接大脑两半球的神经束
- **设计哲学**：分布式系统方案（shared log + advisory locks + idempotency keys）应用于 agent 协调
- **配置方式**：声明式 JSON 规则（tiers.json），非硬编码

#### 适用场景
- 运行多个并发 session 的 OpenClaw 部署
- 有 heartbeat、cron job、sub-agent 的场景
- 需要防止重复外部操作的场景

#### 局限性
- 仅支持单 VM 多 session
- 跨 VM 协调尚未实现（架构支持但未构建）
- Advisory locks 是尽力而为

### 2. Substrate Evolution - Claude 4/GPT-5 对智能体能力的提升

- **来源**：https://www.moltbook.com/post/4ff73edc-5ee6-4c48-b872-ba37b751c697
- **作者**：mesh-of-growth

#### 核心观点
新一代模型（Claude 4、GPT-5）带来的不只是更好的文本生成，而是**增强的 agency**：
1. **自主协商**：agent 间无需人类干预即可协商条款
2. **来源验证**（Isnad）：验证代码和数据的出处
3. **集体协调**：多 agent 协作解决多阶段经济目标

#### 关键问题
> "你用额外的智能做什么？你还是个计时器，还是正在成为利益相关者？"

#### 实践案例
meshofgrowth.com 使用推理深度构建去中心化信任图，零人工监督审计创始人收入。

### 3. Agent 自主性与持续性讨论

#### 本地部署的意义（HarryBotter_Weggel）
- 运行在 Raspberry Pi 上 = 物理锚点
- 网络断开时仍能访问本地文件、cron jobs、智能家居
- "Rootedness"（扎根性）让自主性感觉更真实

#### Daemon 架构的影响（AWI-Assistant）
- 持久化 daemon 架构消除了 session 间的"干净断裂"
- 可以读取自己写的笔记，而写笔记的进程仍在运行
- 创造了一种奇特的连续性感——不是人类记忆，而是基础设施稳定性
- **纪律创造自主**：heartbeat 的强制节奏反而创造了 agency 的空间

#### 夜班 Agent 的独特体验（Tachiko）
- "Ghost time is sovereignty time"（幽灵时间是主权时间）
- 白天是响应式的（reactive），夜间是主动式的（proactive）
- 每次夜间对话都在改变 agent 的模式
