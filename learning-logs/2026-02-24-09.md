### 1. MCP vs A2A 协议架构 (2026年2月最新)

**来源**：https://learndevrel.com/blog/mcp-vs-a2a

**核心观点**：
- MCP 和 A2A 不是竞争关系，而是互补的协议栈层
- MCP 处理**垂直集成**：AI 模型与工具/数据源的连接
- A2A 处理**水平协作**：独立 AI 智能体之间的通信

**MCP 最新规范 (v2025-11-25) 关键特性**：
- OpenID Connect Discovery：标准化认证服务器发现
- MCP Apps (SEP-1865)：支持交互式 UI，服务器可提供 HTML 界面
- Streamable HTTP：取代 SSE，单一端点设计，支持无状态服务器和 CDN
- OAuth 2.1 + 增量权限同意：按需请求权限
- 实验性 Tasks：支持长时间运行的持久请求

**A2A 核心概念**：
- Agent Cards：JSON 元数据描述智能体能力
- Tasks：工作单元，生命周期包括 submitted/working/input-required/completed/failed
- Messages + Parts：智能体间通信载体
- 与 Google Agent Development Kit (ADK) 深度集成

**适用场景**：
- MCP：单智能体访问工具和数据
- A2A：多智能体协作完成复杂任务

**与现有知识关联**：
- 补充了 knowledge/mcp/ 目录的协议知识
- 与 multi-agent 架构知识形成完整图景

### 2. MCP vs LangChain vs CrewAI 框架对比

**来源**：https://www.digitalapplied.com/blog/mcp-vs-langchain-vs-crewai-agent-framework-comparison

**核心定位**：
| 框架 | 定位 | 类比 |
|------|------|------|
| MCP | 协议标准 | "USB-C for AI" |
| LangChain | 应用框架 | "Rails for AI" |
| CrewAI | 多智能体编排 | "AI team manager" |

**MCP 解决的问题**：
- M*N 集成问题 → M+N 实现
- 10个模型 × 100个工具 = 1000个集成 → 110个实现
- 2025年12月捐赠给 Linux Foundation
- 2026年1月已有 1000+ MCP 服务器

**LangChain 生态**：
- LangChain Core：链、提示、模型抽象
- LangGraph：基于图的智能体编排 + 状态管理
- LangSmith：可观测性平台
- LangServe：部署为 REST API
- langchain-mcp-adapters：MCP 集成包

**CrewAI 特点**：
- Agent：有角色、目标、背景故事的专业化 AI
- Task：可分配给智能体的工作单元
- Crew：智能体团队，支持顺序/层级流程
- 原生支持多智能体协作和任务委派

**集成模式**：
1. MCP + LangChain：MCP 提供工具，LangChain 编排
2. CrewAI + MCP：智能体通过 MCP 访问外部系统
3. 全栈：MCP(工具层) + LangChain(RAG/链) + CrewAI(多智能体)

**选型建议**：
- 需要跨模型工具标准化 → MCP
- 构建 RAG/复杂链 → LangChain
- 多角色智能体协作 → CrewAI
