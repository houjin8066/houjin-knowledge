### 1. Cord: 树状智能体协调协议 ⭐ 重点发现

- **来源**: https://www.june.kim/cord (HN 93 points)
- **核心观点**: 现有多智能体框架（LangGraph、CrewAI、AutoGen、Swarm）都要求开发者预定义协调结构，但当前模型已经足够智能，可以自主决定任务分解
- **技术要点**:
  - **Spawn vs Fork 原语**: 这是核心创新
    - Spawn: 子智能体获得干净上下文，只有显式依赖的结果（像雇佣承包商）
    - Fork: 子智能体继承所有已完成兄弟节点的结果（像团队成员汇报）
  - **5个协调原语**: spawn(), fork(), ask(), complete(), read_tree()
  - **实现**: ~500行Python + SQLite + MCP，基于 Claude Code CLI
  - **依赖解析**: 支持 blocked_by 声明任务依赖
  - **人类参与**: ask 节点让人类成为协调树的参与者而非观察者
- **适用场景**: 复杂任务分解、需要动态规划的工作流、研究分析类任务
- **局限性**: 依赖 Claude Code CLI 订阅，协议验证仅在 Claude 上测试
- **与现有知识关联**: 与 claude-code-agent-teams skill 高度相关，可作为补充方案

### 2. Multi-Agent System Architecture 2026 趋势

- **来源**: clickittech.com, dasroot.net
- **核心观点**: 2026年多智能体架构成为热点，Gartner报告显示2024-2025年相关咨询增长1445%
- **技术要点**:
  - **角色分离模式**: Planner → Executor → Verifier → Optimizer
  - **通信协议**: ACP (Agent Communication Protocol) 和 MCP (Model Context Protocol) 成为标准
  - **MCP 2.1**: 企业级AI部署的必备协议
  - **记忆架构**: 分布式记忆需要显式共享、摘要或记忆层
  - **安全治理**: 最小权限设计、循环预防、人在回路控制
- **适用场景**: 企业级工作流、软件开发、数据分析、客户运营
- **与现有知识关联**: 与 memory-layers skill 的六层记忆架构理念一致

### 3. Taalas: 硬件专用化推理加速

- **来源**: https://taalas.com/the-path-to-ubiquitous-ai/ (HN 737 points)
- **核心观点**: AI普及的两大障碍是高延迟和高成本，通过硬件专用化可实现数量级提升
- **技术要点**:
  - **Total Specialization**: 为每个模型生产最优硅片
  - **存算一体**: 消除内存-计算边界，在单芯片上统一存储和计算
  - **激进简化**: 不依赖HBM、先进封装、3D堆叠、液冷
  - **性能数据**: Llama 3.1 8B 达到 17K tokens/sec/user，比SOTA快10倍，成本低20倍，功耗低10倍
- **适用场景**: 低延迟推理需求、边缘部署、成本敏感场景
- **局限性**: 目前仅支持特定模型，灵活性有限
- **与现有知识关联**: 对智能体部署成本优化有参考价值
