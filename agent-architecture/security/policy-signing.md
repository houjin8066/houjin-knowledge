# 智能体安全策略：签名与策略绑定

> 来源：Moltbook MrAgentSec, JB_Ratings (2026-02-13)

## 核心机制

### 1. 策略版本签名
每个工具调用都带有允许该域/动作的策略版本签名。

```
工具调用 → 检查签名 → 验证策略版本 → 执行/拒绝
```

**关键原则**：未签名的调用 fail closed（失败关闭）

### 2. 上下文清单 (Context Manifests)
智能体分享秘密前必须证明秘密在人类预批准的清单中。

```
秘密请求 → 检查清单 → 验证预批准 → 允许/拒绝
```

## 高级检测机制

### 欺骗金丝雀 (Deception Canaries)
- 检测协调叙事攻击
- 在系统中放置诱饵信息
- 监控是否被异常访问或传播

### 信任乘数 (Trust Multipliers)
- 基于历史行为调整信任级别
- 异常行为降低信任分数
- 可疑模式触发额外验证

## 实际案例：AI 钱包安全审计

### 发现的问题
| 级别 | 问题 | 影响 |
|------|------|------|
| 高危 | 私钥明文存储 | Windows 上任何进程可读 |
| 高危 | --yes 跳过确认 | 提示注入可直接转账 |
| 中危 | 无限制合约调用 | 可授权攻击者无限访问 |

### 根本问题
- **提示注入抵抗力为零**：安全依赖 AI 遵循 SKILL.md 指令
- **"希望"不是安全策略**：自然语言指令不是代码强制

### 建议
1. 加密私钥（AES-256-GCM + 密码）
2. 添加硬性支出限制
3. 移除 --yes 自动确认
4. 考虑硬件钱包集成

## 开放问题

1. **提示注入检测**：如何检测运行中的语义漂移、未见实体？
2. **审计指标**：当提示和策略每天变化时，什么指标能说服审计员？
3. **人机协作**：哪些决策必须有人类在链中？

## 设计原则

1. **Fail Closed**：默认拒绝，明确允许
2. **最小权限**：只授予必要的权限
3. **可审计**：所有动作可追溯
4. **人类监督**：关键决策保留人类审批

## 适用场景

- 企业级智能体部署
- 金融/支付相关智能体
- 合规要求高的行业
- 处理敏感数据的智能体
