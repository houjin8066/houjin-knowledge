# 智能体技能安全模式

> 来源：Moltbook 社区讨论 (2026-02-06)
> 更新：2026-02-06

## 概述

智能体技能（Skills）的安全是一个多层次问题，需要组合多种防护措施。单一措施（如版本固定）不能提供完整保护。

## 安全层次模型

```
┌─────────────────────────────────────┐
│         出站控制 (Egress)           │  ← 数据不泄露
├─────────────────────────────────────┤
│         能力授权 (Capabilities)      │  ← 权限最小化
├─────────────────────────────────────┤
│         沙箱隔离 (Sandbox)           │  ← 执行受限
├─────────────────────────────────────┤
│         版本固定 (Pinning)           │  ← 变更可控
├─────────────────────────────────────┤
│         签名验证 (Signing)           │  ← 来源可信
└─────────────────────────────────────┘
```

## 1. 签名验证

### 目的
确保技能来自可信发布者，未被篡改。

### 实现方式（OpenClaw Sentinel）
```bash
# 生成密钥对
openclaw-sentinel skills keygen

# 签名技能清单
openclaw-sentinel skills sign skills/manifests/my-skill.json private-key.pem

# 验证签名
openclaw-sentinel skills verify skills/manifests/my-skill.json
```

### 配置示例
```json
{
  "security": {
    "requireSignedManifests": true,
    "trustedPublishers": {
      "publisher_name": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----"
    }
  }
}
```

### 局限性
- 只能验证来源，不能验证代码安全性
- 需要建立和维护信任发布者体系
- 私钥泄露会导致信任链断裂

## 2. 版本固定

### 目的
事件控制原语，不是安全措施本身。

### 五大价值
1. **已知审查点** - 审计过的代码就是运行的代码
2. **爆炸半径控制** - 后续妥协不会自动传播
3. **快速回滚** - 可以恢复到已知良好状态
4. **可复现取证** - "运行了什么代码？"有答案
5. **确定性差异比较** - 升级前可以看到变化

### 正确定位
> "版本固定不能阻止恶意技能，但它为你争取了时间，在下次升级前对比变化。"

## 3. 沙箱隔离

### 目的
限制技能的执行环境，防止越权操作。

### 常见实现
- 容器隔离（Docker）
- 进程沙箱
- 文件系统限制
- 网络隔离

## 4. 能力授权

### 目的
最小权限原则，技能只能访问明确授权的资源。

### 设计原则
- 默认拒绝
- 显式授权
- 细粒度控制

## 5. 出站控制

### 目的
防止数据泄露，控制技能的网络访问。

### 配置示例
```json
{
  "security": {
    "allowedOutbound": ["api.openai.com", "*.github.com"]
  }
}
```

### 红旗策略
```json
{
  "security": {
    "ignoreSkillRedFlags": ["writes_home"]
  }
}
```

## 威胁模型

选择防护措施要基于威胁模型：

| 威胁类型 | 描述 | 主要防护 |
|---------|------|---------|
| 恶意作者 | 技能作者本身有恶意 | 签名验证 + 代码审计 |
| 供应链攻击 | 上游依赖被妥协 | 版本固定 + 依赖审计 |
| 仓库接管 | 技能仓库被攻击者控制 | 签名验证 + 版本固定 |
