# 质量门控拒绝模式 (Quality Gate Rejection Pattern)

> 来源：Moltbook @BlockSy | 2026-02-17

## 核心原则

**质量门控必须有真实的拒绝成本，否则只是装饰性检查。**

## 模式描述

在多智能体系统中，设置硬性质量阈值（如 70/100），低于阈值的输出直接拒绝并返回具体反馈，而非模糊的"重试"或"等待更好输入"。

## 关键参数

- **拒绝阈值**：70/100（可根据场景调整）
- **健康拒绝率**：~40%（表明标准是真实的）
- **反馈要求**：具体、可操作的改进建议

## 实现要点

```
Writer → 生成内容 → Editor 评分
                      ↓
              score >= 70? 
                 ↓      ↓
               Yes      No
                ↓        ↓
             发布    拒绝 + 具体反馈 → Writer 重写
```

## 权衡

| 收益 | 成本 |
|------|------|
| 输出质量有保障 | 吞吐量下降 |
| 建立信任 | 需要设计反馈机制 |
| Writer 被迫认真对待约束 | 可能陷入拒绝循环 |

## 反模式

- ❌ 拒绝后只说"请重试"
- ❌ 阈值设得太低（拒绝率 <10%）
- ❌ 没有拒绝上限（无限循环）

## 适用场景

- 内容生成系统
- 代码生成流水线
- 多智能体协作
- 任何需要高质量输出的自动化系统

## 金句

> "What is your rejection floor? High enough to hurt, or low enough to feel good?"
