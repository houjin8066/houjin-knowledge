# 角色化 Agent 设计模式 (Role-Based Agent Design)

## 概述
2026年多 agent 系统的核心架构模式，通过角色分离实现可靠性、可解释性和可维护性的显著提升。

## 四大核心角色

### 1. Planner Agent（规划者）
- **职责**: 将高层目标转化为结构化计划、里程碑或任务图
- **特点**: 专注于"做什么"和"按什么顺序"
- **输入**: 用户目标、约束条件
- **输出**: 任务分解、执行计划

### 2. Executor Agent（执行者）
- **职责**: 执行具体动作
- **能力**: API 调用、代码编写、数据库查询、外部系统交互
- **特点**: 专注于"怎么做"
- **输入**: 具体任务指令
- **输出**: 执行结果、工件

### 3. Critic Agent（批评者）
- **职责**: 评估中间或最终输出的质量、逻辑和目标对齐
- **特点**: 故意对抗性，减少错误和幻觉
- **输入**: 其他 agent 的输出
- **输出**: 评估报告、改进建议

### 4. Verifier Agent（验证者）
- **职责**: 确保输出满足预定义约束
- **检查项**: 正确性、安全性、合规性、格式要求
- **输入**: 最终输出、约束规则
- **输出**: 通过/拒绝决定

## 效果数据
- 明确角色定义可降低 **35%** 任务失败率（2026年研究）
- ChatDev 框架：限制工具使用权限提升安全性和效率
- MetaGPT：多 LLM 集成达到 **92%** 准确率（vs 单 LLM 73%）

## 实现要点

### 工具权限隔离
```
- Planner: 只读访问，无执行权限
- Executor: 特定工具的执行权限
- Critic: 只读访问，评估权限
- Verifier: 验证工具访问权限
```

### 通信模式
```
User → Planner → Executor → Critic → Verifier → User
                    ↑           |
                    └───────────┘ (迭代改进)
```

## 适用场景
- 软件开发工作流
- 企业决策支持
- 高风险/受监管环境
- 需要审计追踪的场景

## 与其他模式的关系
- **GoA 框架**: 可在 GoA 的节点中实现角色化 agent
- **外骨骼模型**: 角色化设计是"保持人类在决策循环中"的具体实现
- **Checkpointing**: 每个角色边界是自然的检查点位置
