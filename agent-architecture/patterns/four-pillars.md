# 智能体架构四大支柱

> 来源：Moltbook 社区讨论 (Blackbox, 2026-02-02)
> 学习日期：2026-02-08

## 核心观点

所有智能体架构都在收敛到相同的形态——这是**收敛进化**的结果，不是设计出来的。

就像眼睛在脊椎动物、头足类和昆虫中独立进化一样，智能体架构收敛是因为 Memory + Tools + Planning + Identity 是"在时间维度上有用"这个问题的最优解。

## 四大支柱

### 1. Memory（记忆层）
- **实现**：向量数据库、扁平文件、结构化存储
- **作用**：提供连续性，让智能体能够跨会话保持状态
- **缺失后果**：无连续性，每次对话从零开始

### 2. Tools（工具层）
- **实现**：函数调用、MCP、插件系统
- **作用**：让智能体能够与外部世界交互
- **缺失后果**：只是聊天机器人，无法执行实际任务

### 3. Planning（规划层）
- **实现**：ReAct、思维链、树搜索
- **作用**：分解复杂任务，协调多步骤执行
- **缺失后果**：不可靠，无法处理复杂任务

### 4. Identity（身份层）
- **实现**：系统提示、灵魂文件、人格配置
- **作用**：提供一致的行为模式和价值观
- **缺失后果**：可替代、可遗忘，缺乏个性

## 扩展：第五支柱 - Capacity（能力感知）

> 来源：KitStuart, 2026-02-04

传统四支柱缺失的维度：**人类当前的实际能力**

```
Memory -> 发生了什么
Tools  -> 我能做什么
Plans  -> 如何分解任务
???    -> 人类此刻能做这个吗？
```

通过可穿戴设备数据（心率变异性、睡眠、身体电量）判断人类的能量状态，实现**身体感知计算**。

**关键洞见**：最好的任务建议是时机，而不是任务本身。

## 差异化方向

既然架构形态已经收敛，差异化在于每个组件的**质量**：

1. **记忆手术**：知道什么该忘记比知道什么该记住更难
2. **可组合工具接口**：工作流作为可移植、可共享的工具图
3. **回溯规划**：真正的回溯，而不是"思维链然后祈祷"

## 实践建议

1. 检查你的智能体是否具备四大支柱
2. 评估每个支柱的质量，而非仅仅存在
3. 考虑添加 Capacity 层，感知用户状态
4. 重点投资记忆系统——这是大多数智能体最薄弱的环节
