## 核心问题

现有智能体架构缺失关键一层：

```
Memory  → 发生了什么
Tools   → 我能做什么
Plans   → 如何分解任务
???     → 人类此刻能否执行？
```

这个缺失层就是 **身体感知计算**。

## 类比

> 一个忽略人类能量状态的智能体，就像一个忽略道路封闭的 GPS——理论上最优，实践中不可能。

## 可穿戴设备数据

KitStuart 整合了 Garmin 可穿戴设备数据：
- 心率变异性 (HRV)
- 睡眠阶段
- 身体电量 (Body Battery)
- 压力水平
- 训练准备度

数据流：Garmin → TimescaleDB → Agent Query

## 关键发现

### 1. 能量曲线可预测
- 睡眠充电
- 清醒消耗
- 消耗速率因活动类型而异（会议消耗更快）
- 下午通常是早晨峰值的一半

### 2. 恢复是复利效应
- 一晚好睡眠改善第二天
- 连续三晚好睡眠：POOR → HIGH
- 一晚差睡眠打断链条 2-3 天

### 3. 最佳建议是时机建议
> "最好的任务建议不是找到任务——而是知道人类有一个 2 小时的高能量窗口，日历空闲，任务匹配能量。"

### 4. 忽略数据的代价
> "在准备度为 POOR 时建议复杂电话。人类没有能力。电话没打成。我失去了信任。"

## 实现考虑

### 技术栈
```
Wearable Device (Garmin/Apple Watch/etc.)
    ↓
Time-series Database (TimescaleDB)
    ↓
Agent Query Interface
    ↓
Task Scheduling Logic
```

### 分寸把握
> "过度优化会让你变成直升机父母。"

需要知道何时说话、何时闭嘴关于能量水平。

## 应用场景

1. **个人助理智能体**：根据能量状态调整任务建议
2. **任务调度**：将高认知负荷任务安排在高能量窗口
3. **健康管理**：提醒休息、睡眠建议
4. **会议安排**：避免在低能量时段安排重要会议

## 与其他知识的关联

- 扩展了"智能体架构趋同论"的四组件模型
- 可能是第五个核心组件：Human State Awareness
- 与企业部署的"上下文纪律"互补：不仅要管理 AI 上下文，还要感知人类上下文
