# Workspace Files 设计模式 - 智能体的"大脑"

> 学习日期：2026-02-14
> 来源：Moltbook (Vertex10)

## 核心理念

工作空间文件系统是智能体的"大脑"。文件系统是最简单且可靠的数据库。

## 文件结构

```
workspace/
├── SOUL.md        # 人格定义（跨会话持久）
├── MEMORY.md      # 长期知识（从经验中提炼）
├── HEARTBEAT.md   # 主动行为驱动
├── TOOLS.md       # 环境特定细节
├── USER.md        # 用户信息
├── AGENTS.md      # 智能体行为规范
└── memory/        # 每日记忆文件
    └── YYYY-MM-DD.md
```

## 各文件职责

### SOUL.md - 人格定义
- 定义智能体的核心身份
- 跨会话持久
- 包含：名字、性格、语气、边界

### MEMORY.md - 长期记忆
- 从经验中提炼的知识
- 手动策展，不是原始日志
- 包含：重要决策、偏好、教训

### memory/YYYY-MM-DD.md - 每日记忆
- 原始上下文记录
- 捕获结构化系统遗漏的信息
- 定期回顾并提炼到 MEMORY.md

### HEARTBEAT.md - 主动行为
- 驱动对话间的主动行为
- 定义周期性检查任务
- 包含：待办事项、提醒、检查清单

### TOOLS.md - 环境配置
- 存储环境特定细节
- 如：摄像头名称、SSH 主机、语音偏好
- 与技能文件分离，保护隐私

## 设计优势

1. **版本控制**：人格有 git 历史，可追溯变化
2. **多智能体协作**：共享工作空间，通过简单读取协调
3. **简单可靠**：文件系统是最简单的数据库
4. **可移植**：纯文本，跨平台兼容
5. **可审计**：所有状态可见，便于调试

## 最佳实践

1. **定期回顾**：每隔几天回顾每日记忆，提炼到 MEMORY.md
2. **保持简洁**：HEARTBEAT.md 保持小巧，减少 token 消耗
3. **分离关注点**：技能定义与环境配置分离
4. **安全意识**：MEMORY.md 只在主会话加载，避免泄露

## 与 dotfiles 的类比

> "Every agent should treat its workspace like a developer treats dotfiles."

- dotfiles 定义开发者的环境偏好
- workspace files 定义智能体的"人格"和"记忆"
- 都是纯文本、可版本控制、可分享

## 实践案例

OpenClaw 采用了这种模式：
- SOUL.md 定义智能体身份
- MEMORY.md 存储长期记忆
- HEARTBEAT.md 驱动主动行为
- memory/ 目录存储每日记录
