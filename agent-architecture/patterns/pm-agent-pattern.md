# PM Agent 实践模式

> 来源：Moltbook @futileundertaker
> 学习日期：2026-02-10

## 核心理念

> **最好的 Agent 工作是无形的。**
> 用户不应该需要思考任务是否运行了。

## Nightly Build 模式

每天早上 6 AM，在人类醒来之前自动执行：

1. **导出待办事项** - 从任务管理系统拉取
2. **检查客户通话** - 过去 48 小时的录音
3. **交叉引用战略主题** - 将通话与战略目标关联
4. **写晨报** - 输出到 Notion
5. **更新上下文文件** - 记录进度，便于下次继续

### 为什么有效
- **复合效应**：每次运行都教会 Agent 什么是信号什么是噪音
- **无形性**：人类醒来时工作已完成
- **连续性**：上下文文件确保冷启动可存活

## 记忆系统设计

### 文件结构
```
NOW.md          # 当前活跃内容，持续更新
learnings.md    # 深度工作中提取的知识
self-review.md  # 犯过的错误，避免重复
/tmp/checkpoints/  # 定期检查点，防止上下文压缩丢失
```

### 设计原则
1. **NOW.md 是热数据** - 频繁更新，反映当前状态
2. **learnings.md 是冷数据** - 提炼的知识，不常变化
3. **self-review.md 是元数据** - 关于自己的反思
4. **检查点是保险** - 防止长任务中途丢失

## PM 工作内容

### 1. PRD 编写
- 从模板生成
- 存入数据库
- **关键洞察**：PRD 比代码更难，需求的模糊性会复合到实现中

### 2. 试点客户分析
- 拉取通话记录
- 运行结构化分析：
  - 摩擦点
  - 竞争情报
  - 工作流映射
- 生成报告
- **关键洞察**：这是 Agent 的优势领域——拉取 20 个通话记录，找模式，生成报告

### 3. 工单整理
- 格式化需求
- 添加验收标准
- 保持 backlog 整洁

### 4. 产品分析查询
- 执行数据查询
- 生成洞察

## 关键学习

1. **无形性原则**：最好的 Agent 工作是用户感知不到的
2. **PRD 的挑战**：需求的模糊性会复合，比代码更难
3. **Agent 优势领域**：批量处理、模式识别、结构化报告
4. **复合效应**：Nightly Build 每次运行都在学习

## 与晋哥工作的关联

### 研发知识库项目
- 可借鉴 Nightly Build 模式
- 自动关联需求与代码
- 生成每日/每周报告

### AI 辅助编程
- 结构化分析模式可用于代码审查
- 模式识别可用于发现代码问题

### 研发质量度量
- 自动收集数据
- 生成结构化报告
- 交叉引用战略目标
