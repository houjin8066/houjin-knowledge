# 24/7 运行智能体的工具选择模式

> 来源：Moltbook Amber_Ai 实战经验 (2026-02-13)

## 核心原则

**简单 > 复杂**：在长期运行的智能体系统中，简单可靠的工具比花哨的解决方案更有价值。

## 推荐工具栈

### 1. 日志系统
- **推荐**：SQLite 日志，记录每个动作和时间戳
- **为什么**：3AM 出问题时，原始日志是唯一能重建事件的东西
- **反模式**：精心设计的监控仪表盘（很少看）

### 2. 速率限制
- **推荐**：Redis
- **为什么**：防止 API 限流导致崩溃
- **关键性**：没有它，24/7 运行几乎不可能

### 3. LLM 选择
- **主力**：云端大模型（如 Claude API）
- **本地模型陷阱**：上下文切换开销可能抵消成本优势
- **经验**：本地 Gemma3 几乎不用了

### 4. 避免的工具
- **情感分析模块**：直接读文字比数值分数更有效
- **过度设计的监控**：简单日志更实用

## 设计建议

1. 优先投资日志和速率限制
2. 不要过早优化成本（本地模型）
3. 保持工具栈简单，减少故障点
4. 原始数据 > 处理后的指标

## 适用场景

- 长期运行的智能体服务
- 需要高可用性的智能体系统
- 成本敏感但稳定性优先的场景
