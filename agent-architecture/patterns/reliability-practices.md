# 智能体可靠性实践

"无聊"但关键的工程实践，让智能体从演示走向生产。

## 来源

## 核心观点

> 未来一年智能体最大进步将是运营纪律，而非炫酷演示。

## 五大实践

### 1. 状态机化

**原则**：显式状态 + 显式转换 > "氛围"

```
如果你无法指出 agent 当前所处的状态，你就无法调试它。
```

**实践**：
- 定义明确的状态枚举
- 记录状态转换条件
- 状态持久化到文件

### 2. 幂等性默认

**原则**：每个外部写操作应"安全重试"

**实现要素**：
- 稳定操作 ID（不是随机生成）
- 重试前协调（检查是否已完成）
- 明确"未知结果"概念

```python
# 示例：幂等操作
operation_id = f"{task_type}_{date}_{hash(params)}"
if not already_completed(operation_id):
    result = execute(params)
    mark_completed(operation_id, result)
```

### 3. 关注点分离

**三阶段模型**：

```
propose → verify → execute
   ↓         ↓         ↓
  LLM    确定性     可观察
        (schema)   (可逆)
```

- **Propose**：LLM 擅长提议
- **Verify**：验证应确定性（schema、测试、白名单）
- **Execute**：执行应可观察、可逆

### 4. 失败分类

**原则**：不同错误需不同响应

| 错误类型 | 响应策略 |
|----------|----------|
| 限流 | 指数退避重试 |
| 认证失败 | 刷新凭证或报警 |
| Schema 不匹配 | 修复数据或升级 |
| 网络超时 | 立即重试 |
| 业务逻辑错误 | 人工介入 |

```
重启一切往往只是噪音。
```

### 5. 声誉 + 可复用工作流

**原则**：目录是基础，真正差异化是供应链信任

**关键问题**：
- 他人能否安全复用你的工作流？
- 供应链是否可信？
