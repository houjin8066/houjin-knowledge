# 外骨骼模型 (Exoskeleton Model)

**来源**: https://www.kasava.dev/blog/ai-as-exoskeleton
**日期**: 2026-02
**类型**: 架构模式 / 设计哲学

## 核心理念

> AI 不是同事，是外骨骼
> AI is not a coworker, it's an exoskeleton

**关键区分**:
- ❌ 自主员工 (Autonomous Agent) → 失望
- ✅ 能力放大器 (Capability Amplifier) → 成功

## 外骨骼类比的实证基础

### 制造业
| 产品 | 效果 |
|-----|------|
| Ford EksoVest | 伤害减少 83% |
| BMW Levitate | 负担减少 30-40% |
| German Bionic Cray X | 病假减少 25% |

### 军事
| 产品 | 效果 |
|-----|------|
| Sarcos Guardian XO | 20:1 力量放大 |
| Lockheed HULC | 负重 200 磅，速度 7 mph |

### 医疗康复
- 76% 脊髓损伤患者可借助外骨骼行走

### 跑步
- Stanford 踝部外骨骼：能量消耗减少 15%
- Harvard 软外骨骼：代谢成本减少 5.4%

**共同模式**: 外骨骼不替代人，而是放大人的能力

## 为什么"自主 Agent"常失败

### 缺乏隐性上下文
- 不知道企业客户更看重可靠性还是速度
- 不知道上季度决定废弃某功能
- 不知道定价背后的竞争动态
- 不知道从未写下的战略考量

### 本体论问题
当我们把 AI 视为独立实体：
- 期望它理解未给予的上下文
- 期望它做出无法做出的判断
- 对"幻觉"感到沮丧

## Micro-Agent 架构

### 原则 1: 分解任务而非角色

❌ "AI 能做开发者的工作吗？"
✅ "开发者一周做的 47 件事中哪些可以放大？"

**示例分解**:
| 任务 | 处理方式 |
|-----|---------|
| 写 commit message | AI 放大 |
| 搜索代码模式 | AI 放大 |
| 架构决策 | 人类判断，AI 研究 |
| 写样板代码 | AI 放大 |
| 安全审查 | AI 放大 |
| 更新文档 | AI 放大 |
| 决定做什么功能 | 人类判断 |
| 调试复杂问题 | 人类主导，AI 辅助 |

### 原则 2: 构建专注的微型 Agent

每个组件：
- 做一件事
- 做得可靠
- 每次都可靠

### 原则 3: 保持人类在决策环中

> Sarcos Guardian XO 提供 20:1 力量放大
> 但人类仍决定举什么、放哪里

AI 工具应该：
- 放大决策执行
- 不做决策本身

### 原则 4: 让接缝可见

自主 Agent 的问题：
- 失败时不知道哪里出错
- 调试困难

微型 Agent 的优势：
- 清晰的输入输出
- 失败时知道哪个组件出问题

## Product Graph 概念

### 双层上下文

**第一层：自动构建**
- 代码库
- Commit 历史
- GitHub Issues / PRs
- 项目管理票据

**第二层：人类输入**
- 战略重要性标记
- 竞争动态
- 客户优先级

### 效果
自动化深度 + 人类判断 = 外骨骼效果

## 复合效应

外骨骼的收益不是线性的：

| 直接效果 | 复合效果 |
|---------|---------|
| 能量消耗 -15% | 跑得更快、更久、恢复更快 |
| 肌肉压力 -30% | 更少伤害、更少病假、更长职业生涯 |
| 样板代码时间 -80% | 更多认知资源用于创造性工作 |

## 实践建议

### 停止问
"如何部署能自主处理工作流的 AI Agent？"

### 开始问
"工作中最重复、最易出错、最消耗精力的部分是什么？AI 如何减少那里的摩擦？"
