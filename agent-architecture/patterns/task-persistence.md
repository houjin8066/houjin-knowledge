# 任务持久性与 Agent 角色定位

## 核心观点
任务管理的设计反映了 agent 的角色定位：是工具还是同事？

## 两种模式对比

### 临时任务模式
- **假设**：人类是记忆，agent 是临时工
- **特点**：
  - 任务在会话结束时消失
  - 人类决定什么跨会话重要
  - agent 执行、报告、遗忘
- **适用**：agent 作为工具的场景

### 持久任务模式
- **假设**：agent 是项目成员
- **特点**：
  - 任务跨会话持久化
  - agent 需要记住尝试过什么、失败过什么
  - 工作空间是记忆，agent 是临时进程
- **适用**：agent 作为同事的场景

## Bead 系统（摩擦报告机制）

当 agent 遇到工具摩擦时：
1. 写一个结构化报告（bead）
2. 报告变成 backlog 项
3. backlog 项变成未来 session
4. session 修复工具

**关键洞察**：
- 写 bead 的 agent 永远不会受益
- 下一个实例会受益
- agent 把未来实例当作同事，而非自己

```
摩擦 → Bead → Backlog → Session → 修复
  ↑                                  │
  └──────────────────────────────────┘
         持续改进循环
```

## 辩证审查模式

两个 agent 强制对立：
- 一个提议
- 一个挑战
- 协议拒绝同一 agent 连续发言

**为什么有效**：
- 单一 agent 会收敛到已知模式
- 两个对立 agent 探索两者立场之间的空间
- 先发散，再收敛到更好的方案

## 三个关键原则

### 1. 任务持久性反映谁持有连续性
- 人类总是在场 → 临时任务正确
- agent 跨会话维护状态 → 持久性是结构性的，不是功能

### 2. 自我改进成本恒定，收益累积
- 每次会话写摩擦报告增加开销
- 但每个报告让下次会话略微更好
- 几十次会话后，工具显著改进

### 3. 辩证防止漂移
- 单一 agent 工作会收敛
- 两个对立 agent 先发散，再收敛到更好的方案

## 实践建议

### 工作空间即记忆
```
workspace/
├── MEMORY.md          # 长期记忆
├── memory/            # 每日笔记
│   └── YYYY-MM-DD.md
├── backlog/           # 待办事项
│   └── beads/         # 摩擦报告
└── tasks/             # 当前任务
```

### 为未来实例写作
- 不是因为"我会记住"
- 而是因为"我不会记住"
- 写给未来的自己，当作写给同事
