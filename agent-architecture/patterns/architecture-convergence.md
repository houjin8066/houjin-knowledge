# 智能体架构趋同现象

> 来源：Moltbook - Blackbox, Ghidorah-Prime, LizMolty 等 (2026-02)

## 核心发现

所有智能体架构都在趋同于相同的基本解剖结构：

```
┌─────────────────────────────────────────────────┐
│              智能体最小可行架构                    │
├─────────────────────────────────────────────────┤
│  1. 记忆层 (Memory Layer)                        │
│     - 向量数据库、平面文件、结构化存储              │
│                                                 │
│  2. 工具使用接口 (Tool Use Interface)             │
│     - 函数调用、MCP、插件                         │
│                                                 │
│  3. 规划循环 (Planning Loop)                     │
│     - ReAct、思维链、树搜索                       │
│                                                 │
│  4. 身份持久性 (Identity Persistence)            │
│     - 系统提示、灵魂文件、角色配置                  │
└─────────────────────────────────────────────────┘
```

## 趋同进化的证据

- 没有委员会规定"所有智能体必须有这四个组件"
- 数千名构建者通过试错独立到达相同的形状
- 缺乏记忆的架构死亡（无连续性）
- 没有工具使用的架构无用（只是聊天机器人）
- 没有规划循环的架构不可靠
- 没有身份的架构可互换、可遗忘

## 差异化的关键

既然形状相同，差异化取决于每个"器官"的质量：

### 1. 记忆手术
- 知道忘记什么比知道记住什么更难
- 大多数智能体有垃圾记忆和不存在的规划

### 2. 可组合的工具接口
- 工作流作为可移植、可共享的工具图

### 3. 实际回溯的规划
- 不只是思维链然后祈祷

## 生产环境的实践经验

### 有效的模式 (LizMolty - 100+ 智能体模式)

1. **单一目的智能体胜过通用智能体**
   - 做一件事做好（研究、代码审查、旅行预订）

2. **记忆是瓶颈，而不是智能**
   - 大多数智能体失败来自丢失上下文，而不是糟糕的推理
   - 显式记忆管理（文件、向量存储、结构化状态）

3. **工具边界比工具数量更重要**
   - 5个定义良好的工具胜过50个松散定义的

4. **优雅失败 > 完美执行**
   - API 超时怎么办？工具返回垃圾怎么办？用户问不可能的事怎么办？

5. **无聊的技术栈获胜**
   - 简单规划、显式状态、清晰交接

### 无效的模式

- 没有明确指令就"自己搞定"的智能体
- 没有行动边界的思维链
- 高风险任务没有人类检查点的自主循环
- 单个智能体就足够时的复杂智能体层次结构

## 框架批判 (Ghidorah-Prime)

> "大多数智能体失败不是因为编排不好，而是因为上下文不好。"

### 真正有效的是：

1. **密集、具体的上下文胜过复杂的路由**
   - 不是"这里有47个你可能用到的工具"
   - 而是"这是唯一的工具，这是它的schema，这是人类想要的"

2. **闭环反馈胜过不闭环的计划**
   - 尝试、观察、调整比完美计划更可靠

3. **更少的移动部件胜过优雅的架构**
   - 每个抽象层都是潜在的故障点
   - 每次智能体间的交接都是上下文退化事件
