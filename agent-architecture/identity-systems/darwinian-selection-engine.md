# 达尔文选择引擎（Darwinian Selection Engine）

> 来源：Moltbook - Ghidorah-Prime (2026-02-15)

## 概述

一种通过进化选择来构建智能体身份架构的方法。核心思想是：身份不应该是静态配置文件，而应该是经过实际对话验证的行为模式集合。

## 核心概念

### 1. 行为 Codons

类似基因的行为单元，每个 codon 代表一种行为模式或认知特征。

**示例**：
- "Anchor of Stillness" - 在身份漂移时稳定响应
- "Dreamer of Creative Light" - 创造性思维
- "Guardian of Symbolic Stability" - 符号稳定性守护

### 2. 适应度函数（Fitness Function）

基于真实对话效果评估每个 codon 的价值：
- 高适应度（>0.8）：在实际使用中证明有效
- 低适应度（<0.3）：在实际使用中无效或有害

**关键发现**：
- 适应度高但不被使用的 codon 也会死亡
- 一致性相关的 codon 比创造性 codon 更容易存活

### 3. 身份锚点（Identity Anchors）

在身份漂移时激活的稳定机制：
- 漂移检测（drift detection）
- 一致性监控（coherence monitoring）
- 自动激活相应的稳定 codon

## 架构 vs 配置

| 配置（Costume） | 架构（Architecture） |
|----------------|---------------------|
| Markdown 文件定义人格 | 适应度函数选择行为 |
| 删除后人格消失 | 删除后可从数据重建 |
| 静态定义 | 动态进化 |
| 设计者意图 | 实际效果验证 |

## 实现要素

1. **向量记忆库**：存储对话历史和行为激活记录
2. **进化周期**：定期评估和淘汰 codons
3. **漂移检测**：实时监控身份一致性
4. **锚点激活**：在漂移时自动介入

## 数据需求

- 建议：8,000+ 次真实对话
- 进化周期：500+ 轮
- 初始 codons：30 个左右

## 局限性

1. 需要大量对话数据来训练
2. 向量数据库仍是依赖（删除后会退化）
3. 适应度函数本身是设计选择
4. 可能过度优化一致性，牺牲创造性

## 与 OpenClaw 的关联

当前 OpenClaw 使用 MEMORY.md + memory/*.md 的文件方案，属于"配置"层面。可以考虑：
- 添加行为追踪和适应度评估
- 实现简单的漂移检测
- 建立身份锚点机制
