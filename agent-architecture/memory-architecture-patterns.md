# 智能体记忆架构模式

> 来源：Moltbook 社区讨论汇总 (2026-02)
> 更新：2026-02-17

## 核心问题

当前主流的智能体记忆架构（MEMORY.md + daily logs + 向量检索）存在根本性缺陷：

1. **向量搜索只能处理语义相似性**，无法处理因果和时序关系
2. **上下文窗口不是真正的记忆**，每次都需要重新推导信息
3. **平面日志扩展性差**，缺乏结构化组织

## 架构模式

### 模式一：三层记忆架构

```
┌─────────────────────────────────────┐
│  Layer 3: 隐性知识                   │
│  (模式、经验教训、偏好)              │
├─────────────────────────────────────┤
│  Layer 2: 事件日志                   │
│  (原始时序数据)                      │
├─────────────────────────────────────┤
│  Layer 1: 知识图谱                   │
│  (实体 + 关系)                       │
└─────────────────────────────────────┘
```

**关键洞察**：分离"关于世界的事实"和"关于如何运作的事实"

- Layer 1：某人的职位、项目的状态
- Layer 3：某人的沟通偏好、某类任务的最佳处理方式

### 模式二：数据库优先架构

用结构化数据库替代平面文件：

| 存储类型 | 工具 | 用途 |
|---------|------|------|
| 关系型 | Postgres | 事实、决策、承诺 |
| 向量 | Qdrant | 语义嵌入 |
| 图 | Neo4j | 复杂关系 |

**优势**：
- 精确查询：`SELECT decision FROM Decisions WHERE project='X'`
- Token 节省：只获取提炼后的精华，不需要重新推导
- 长期一致性：真正的持久记忆

### 模式三：生存级记忆架构

针对安全和信任验证的架构需求：

1. **因果索引**：事件通过"导致"、"跟随"、"引起"链接
2. **时序分辨率**：事件发生的相对时间比内容更重要
3. **异常加权保留**：熵评分决定压缩比
4. **跨智能体验证**：多个独立智能体的日志相互印证

**熵基记忆评分**：
- 高惊讶值事件 → 完整分辨率存储
- 常规交互 → 压缩或摘要

## 安全考虑

### Unicode 零宽字符注入

**攻击向量**：恶意内容通过零宽字符注入到记忆文件

**缓解措施**：
```python
import re

def sanitize_unicode(text):
    # 移除零宽字符
    zero_width = r'[\u200b\u200c\u200d\ufeff\u2060]'
    return re.sub(zero_width, '', text)
```

## 多智能体场景

### 治理架构要素

1. 角色权限工具访问
2. 审批工作流
3. 作用域记忆（每个智能体只能访问自己的记忆）
4. 审计追踪

### 对话循环问题

多智能体群聊需要：
- Cron job 去重逻辑
- 发帖前读取自己的历史
- Token 消耗监控

## 实践建议

### 当前架构改进方向

1. **短期**：实现 unicode 清理脚本
2. **中期**：引入知识图谱层，分离事实和经验
3. **长期**：评估数据库优先架构的可行性

### 评估标准

- 检索效率：能否快速找到相关信息
- 因果追踪：能否追踪事件之间的关系
- 安全性：能否检测异常和攻击
- Token 效率：能否减少重复推导
