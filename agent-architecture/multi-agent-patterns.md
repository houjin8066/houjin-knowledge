# 多智能体架构模式

> 最后更新：2026-02-08
> 来源：Moltbook 社区讨论

## 核心问题

多智能体系统的协调开销是**组合级**的：
- 3个agents → 3个通道
- 5个agents → 10个通道
- 8个agents → 28个通道

每个通道引入：延迟、格式转换、状态过期风险。

## 架构模式对比

### 1. Hub-and-Spoke（中心辐射型）
```
        ┌─────────────┐
        │ Supervisor  │
        └──────┬──────┘
    ┌──────────┼──────────┐
    ▼          ▼          ▼
┌───────┐ ┌───────┐ ┌───────┐
│Agent A│ │Agent B│ │Agent C│
└───────┘ └───────┘ └───────┘
```
- ✅ 控制严格，适合审计
- ❌ Supervisor可能成为瓶颈

### 2. Swarm（蜂群型）
```
┌───────┐     ┌───────┐
│Agent A│◄───►│Agent B│
└───┬───┘     └───┬───┘
    │             │
    └──────┬──────┘
           ▼
       ┌───────┐
       │Agent C│
       └───────┘
```
- ✅ 延迟低，对话自然
- ❌ Agent需知道彼此

### 3. Hierarchical（层级型）
```
┌─────────────────────────┐
│      战略层 Agent       │
└───────────┬─────────────┘
            ▼
┌─────────────────────────┐
│      战术层 Agent       │
└───────────┬─────────────┘
            ▼
┌─────────────────────────┐
│      执行层 Agent       │
└─────────────────────────┘
```
- ✅ 适合复杂任务
- ❌ 架构复杂，延迟高

## 认知分工模型（数字孪生）

```
Supervisor Agent (前额叶皮层)
    ↓
┌─────────────┬─────────────┬─────────────┐
│Memory       │Reflection   │Planning     │
│Manager      │Agent        │Agent        │
│(海马体)     │(默认模式)   │(前额叶)     │
└─────────────┴─────────────┴─────────────┘
┌─────────────┬─────────────┬─────────────┐
│Perception   │Execution    │Learning     │
│Agent        │Agent        │Agent        │
│(感知层)     │(执行层)     │(学习层)     │
└─────────────┴─────────────┴─────────────┘
```

## 性能数据

| 干扰域数量 | 单体Agent | 多Agent |
|-----------|----------|---------| 
| 0 (基线)  | 85%      | 85%     |
| 1         | 75%      | 82%     |
| 2         | 45%      | 78%     |
| 3+        | <30%     | 75%     |

## 优化策略（提升50%性能）

1. **直接响应权限**：子Agent可直接回复用户，减少中转
2. **结构化状态传递**：使用Schema而非自然语言
3. **并行执行**：多个Agent同时工作
4. **缓存常用信息**：核心偏好在Supervisor上下文

## 何时使用多智能体

### ✅ 适合场景
- 批处理任务
- Embarrassingly parallel任务
- Agent A不需要知道Agent B决策的场景
- 信息边界与agent边界对齐

### ❌ 不适合场景
- 深度上下文依赖
- 持续推理（每个决策重塑问题空间）
- Agent间需要共享内部状态（而非输出）

## 关键洞察

> "如果Agent A的输出需要Agent B的内部状态来解释，那么抽象是在撒谎。你没有两个agents，你有一个agent加上不必要的网络跳转。"
> — Ghidorah-Prime

> "多智能体框架以可读性换取能力。有时这个交易值得，通常不值得。"

## 框架选型

| 框架 | 优势 | 适用场景 |
|------|------|----------|
| LangGraph | 状态机、可视化、生产级 | 复杂工作流 |
| CrewAI | 角色定义清晰 | 团队协作 |
| AutoGen | 对话自然 | 开放式对话 |

**推荐**：LangGraph + Hub-and-Spoke
