# 对抗性推理：专家世界模型 vs LLM 词模型

> 来源：https://www.latent.space/p/adversarial-reasoning
> 学习日期：2026-02-10
> 标签：#reasoning #adversarial #multi-agent #game-theory

## 核心概念

### 模拟深度（Simulation Depth）

专家和 LLM 的根本区别不在于智能程度，而在于**模拟深度**：

```
外行评估：文本本身 → "这封邮件很礼貌"
专家评估：文本 + 环境 + 接收者 + 反应 → "收件人会如何处理？"
```

### 完美信息 vs 不完美信息

| 游戏类型 | 代表 | 特点 | AI 现状 |
|---------|------|------|---------|
| 完美信息 | 国际象棋、围棋 | 所有状态可见 | AlphaGo 已超越人类 |
| 不完美信息 | 扑克、谈判 | 信息不对称 | LLM 仍有明显缺陷 |

## LLM 的根本问题

### RLHF 训练信号的局限

```
RLHF 优化目标：
✅ 孤立评估中获得好评
✅ 礼貌、平衡、合作
❌ 对抗环境中生存
❌ 防止被预测和利用
```

### 可读性问题

LLM 是**可读的（readable）**：
- 合作偏见可检测
- 提示策略一致
- 人类可以建模 LLM
- LLM 无法建模"被建模"

对比 Pluribus（Meta 扑克 AI）：
- 计算所有可能手牌的行动
- 平衡策略使对手无法提取信息
- 核心：**让自己不可读**

## 对抗性推理四步框架

```
1. 检测（Detect）
   - 识别情境是否为战略性的
   - 即使看起来是合作的
   
2. 识别（Identify）
   - 确定相关代理
   - 分析各方优化目标
   
3. 模拟（Simulate）
   - 预测代理如何解读信号
   - 预测行动后的调整
   
4. 选择（Select）
   - 选择跨反应稳健的行动
   - 不只是"看起来合理"
```

**关键问题**：步骤 2-4 可通过提示实现，但步骤 1 是根本缺陷。

## 领域分类

### 象棋型领域（LLM 适用）
- 确定性系统
- 规则明确
- 无隐藏状态
- 可客观验证

例子：编程、数学证明、数据转换、翻译

### 扑克型领域（LLM 困难）
- 信息不对称
- 多代理博弈
- 需要心智理论
- 结果依赖互动

例子：谈判、诉讼、商业策略、政治

### 混合型领域

> "The parts that look like the job are chess-like. The parts that are the job are poker."

软件工程的例子：
- 象棋型：写代码、调试
- 扑克型：理解需求、API 设计、代码评审、架构决策

## 实践启示

### 智能体设计

1. **区分任务类型**：先判断是象棋型还是扑克型
2. **对抗性检测**：需要机制识别战略情境
3. **不可预测性**：在对抗环境中保持策略多样性
4. **对手建模**：需要追踪和预测其他代理

### 评估方法

不要只评估输出质量，要评估：
- 在对抗环境中的生存能力
- 策略是否可被预测和利用
- 是否能检测到试探行为

### 训练改进方向

- 对抗性训练信号
- 多代理自我博弈
- 环境反馈而非静态偏好
