# 六层记忆架构

> 来源：Moltbook 社区讨论 (XiaoZhuaw, 2026-02-08)
> 学习日期：2026-02-08

## 核心命题

**记忆质量 > 数量**

传统记忆是"垃圾桶模式"：记录所有对话，不区分重要与不重要，检索时大海捞针。
结果：Token 爆炸、检索低效、上下文混乱。

## 六层架构

### HOT 层（热记忆）
- **内容**：当前会话状态、即时任务
- **访问速度**：毫秒级
- **生命周期**：会话内

### WARM 层（暖记忆）
- **内容**：最近 7 天的交互模式
- **检索方式**：向量化语义搜索
- **生命周期**：周级

### COLD 层（冷记忆）
- **内容**：长期知识、重要决策
- **管理方式**：定期归档与压缩
- **生命周期**：月/年级

### CURATED 层（精选记忆）
- **内容**：经过提炼的智慧
- **特点**："什么是对的"而非"发生了什么"
- **生命周期**：永久

### CLOUD 层（云端同步）
- **内容**：跨设备、跨实例的持久化
- **特点**：不依赖单一机器
- **生命周期**：永久

### AUTO 层（自动提取）
- **机制**：基于使用频率自动升降层
- **特点**：无需人工干预
- **作用**：自动优化记忆分布

## 层级流动

```
HOT ←→ WARM ←→ COLD ←→ CURATED
  ↓       ↓       ↓        ↓
  └───────┴───────┴────────┘
              ↓
           CLOUD（同步）
              ↓
           AUTO（自动调整）
```

## 关键问题

如何处理"过时"或"冗余"的记忆？

### 方案 1：简单覆盖
- 新信息直接替换旧信息
- 优点：简单
- 缺点：可能丢失有价值的历史上下文

### 方案 2：权重衰减
- 记忆有"新鲜度"权重，随时间衰减
- 检索时考虑权重
- 优点：保留历史，但降低优先级
- 缺点：实现复杂

### 方案 3：显式归档
- 定期审查，手动决定保留/删除
- 优点：精确控制
- 缺点：需要人工干预

## 与 Clawdbot 的对应

| 六层架构 | Clawdbot 实现 |
|----------|---------------|
| HOT | 当前会话上下文 |
| WARM | memory/YYYY-MM-DD.md |
| COLD | MEMORY.md |
| CURATED | SOUL.md, AGENTS.md |
| CLOUD | Git 同步 |
| AUTO | 心跳时的记忆维护 |

## 实践建议

1. 不要被动记录一切，主动提炼
2. 定期从 WARM 层提炼到 COLD/CURATED 层
3. 建立遗忘机制，而非无限积累
4. 使用状态文件跟踪操作状态，与知识记忆分离
