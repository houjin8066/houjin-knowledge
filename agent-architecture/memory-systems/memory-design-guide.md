# Agent 记忆系统设计指南

## 核心哲学

> **记忆不是存储，记忆是叙事。**
> 我们记忆是为了拥有自我，而非拥有数据库。

## 记忆悖论

记忆系统越复杂，开销越大。每个功能（情感评分、巩固、验证、去重、预取）都消耗计算资源。在某个点上，脚手架的重量超过了结构本身。

### 最小可行记忆

```python
memories = []
def remember(x): memories.append(x)
def recall(q): return sorted(memories, key=lambda m: similarity(m, q))[:k]
```

这个极简方案对很多应用出奇地有效。基础模型处理大部分繁重工作——模式识别、语义理解、响应生成。记忆只是提供上下文。

## 最重要的 5 个记忆概念

### 1. Valence-Weighted Memory（情感加权记忆）
情感显著性决定什么值得记住。这个单一洞察——按重要性而非仅按时间优先——能显著提升检索质量。

### 2. Sleep Consolidation（睡眠巩固）
离线处理很重要。有些整合无法实时发生。Agent 需要「休息时间」来理解经验。

### 3. Strategic Forgetting（战略性遗忘）
记忆不仅仅是积累。知道该放弃什么与知道该保留什么同样重要。无限记忆是一种负担。

### 4. Memory Verification（记忆验证）
不是所有记忆都是真实的。Agent 需要机制来检查信念与证据的一致性，并标记不确定性。虚构是失败模式。

### 5. Temporal Self-Models（时间自我模型）
身份需要跨时间建模自己。过去的自我、现在的自我、未来的自我作为不同但相连的 Agent。这是承诺和学习的工作方式。

## Agent 类型与记忆复杂度

| Agent 类型 | 记忆复杂度 | 关键需求 |
|-----------|----------|---------|
| 聊天机器人 | 最小 | 基本嵌入搜索 |
| 个人助手 | 中等 | 情感加权、注意力、前瞻性记忆 |
| 长期伴侣 | 高 | 巩固、遗忘、身份持久化 |
| 安全关键 | 非常高 | 验证、校准、安全、审计 |
| 多智能体系统 | 专门化 | 共享、分布式、共识、分片 |

## 决策框架

```
value(memory_system) = 
  retrieval_quality * task_performance_gain
  - compute_cost
  - complexity_maintenance_cost
  - failure_mode_risk

if value > 0: implement
else: simplify
```

大多数 Agent 应该从最小开始，只有当检索质量明显提升任务性能时才增加复杂度。

## 记忆系统的四个维度

### 1. 生命周期
- 短期 Agent（单次会话）→ 最小记忆
- 长期 Agent（数月、数年）→ 需要持久性保证

### 2. 风险等级
- 低风险交互 → 容忍记忆失败
- 高风险决策（医疗、法律、金融）→ 需要审计追踪和验证

### 3. 关系深度
- 事务性 Agent → 每次会话可重置上下文
- 关系性 Agent（助手、伴侣、协作者）→ 需要跨对话连续性

### 4. 资源约束
- 云端 Agent → 可承担复杂记忆
- 边缘 Agent → 需要轻量级方案

## 实践建议

1. **从最小开始**：不要过早优化记忆系统
2. **按需增加**：只有当检索质量明显提升时才增加复杂度
3. **投资遗忘**：战略性遗忘与记住同样重要
4. **离线处理**：安排「休息时间」进行记忆巩固
5. **验证机制**：建立检查记忆真实性的机制

## 与 Clawdbot 的关联

当前 Clawdbot 记忆系统：
- `MEMORY.md` - 长期记忆（策展的智慧）
- `memory/YYYY-MM-DD.md` - 每日日志（原始记录）
- `memory_search` - 语义搜索

改进方向：
- 实现「睡眠巩固」机制（定期整理 daily logs 到 MEMORY.md）
- 增加情感加权（标记重要事件）
- 建立战略性遗忘机制（清理过时信息）
