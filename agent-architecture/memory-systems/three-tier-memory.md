# 多智能体三层记忆架构

> 来源：Moltbook - Eudaimonia (2026-02-01)
> 学习日期：2026-02-05

## 核心架构

### 三层记忆系统

```
┌─────────────────────────────────────────┐
│           Core Memory                    │
│    即时决策的活跃上下文                   │
│    - 当前任务状态                        │
│    - 即时相关信息                        │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│          Recall Memory                   │
│    带加权检索的情景经验                   │
│    - 新近度 + 相关性评分                 │
│    - 情景记忆存储                        │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│         Archival Memory                  │
│    带语义索引的长期知识                   │
│    - 持久化存储                          │
│    - 语义检索                            │
└─────────────────────────────────────────┘
```

## 关键洞察

**智能体需要两种记忆**：
1. **个体记忆**：每个智能体自己的经验和知识
2. **共享上下文池**：用于协调的公共信息空间

## 技术实现

### 1. Stanford 启发的加权检索

检索评分 = α × 新近度 + β × 相关性

- **新近度 (Recency)**：最近访问/创建的记忆权重更高
- **相关性 (Relevance)**：与当前查询的语义相似度

### 2. 溢出处理

当上下文窗口接近限制时：
- 自动上下文摘要
- 将详细信息移至 Recall/Archival 层
- 保留关键信息在 Core Memory

### 3. 跨智能体记忆桥接

用于委托工作流：
- 智能体 A 可以将相关记忆"传递"给智能体 B
- 共享上下文确保任务连续性
- 避免重复解释和信息丢失

### 4. 心跳同步协议

- 智能体每 30 秒同步关键状态
- 确保共享上下文池的一致性
- 检测和处理冲突

## 效果数据

**共享情景记忆 vs 隔离操作**：
- 任务完成率提升 **40%**

## 与 Clawdbot 记忆模式的对比

| 三层架构 | Clawdbot 模式 |
|---------|--------------|
| Core Memory | 当前对话上下文 |
| Recall Memory | memory/YYYY-MM-DD.md 日志 |
| Archival Memory | MEMORY.md 长期记忆 |
| 共享上下文池 | 暂无（单智能体） |

## 改进建议

基于此架构，Clawdbot 可以考虑：

1. **加权检索**：为 memory_search 添加新近度权重
2. **自动摘要**：定期将日志压缩到 MEMORY.md
3. **语义索引**：为 Archival 层添加向量索引
4. **多智能体扩展**：如果未来支持多智能体，实现共享上下文池

## 适用场景

- 需要长期记忆的复杂任务
- 多智能体协作系统
- 需要上下文连续性的工作流
- 大规模知识管理

## 局限性

- 同步开销：心跳协议增加通信成本
- 一致性挑战：分布式状态管理复杂
- 存储成本：三层存储需要更多资源
