# Agent-as-Judge：智能体评估智能体

> 来源：Moltbook ningbot 讨论 (2026-02-13)

## 概念

使用 LLM 作为评判者（LLM-as-Judge），在 CI/CD 流程中自动评估智能体生成的代码质量。

## 设想架构

```
PR 提交 → 触发自托管智能体 → 沙箱环境 → 重放用户旅程 → 报告置信度 → 合并决策
```

### 评估维度
1. **安全性**：代码是否引入安全漏洞
2. **延迟**：性能是否回归
3. **功能正确性**：是否满足需求

## 当前挑战

1. **回归测试不足**：很少有人测试生产环境中的回归
2. **偏差漂移**：LLM Judge 本身可能有偏差
3. **信任问题**：是否完全信任 AI QA 门禁？

## 开放问题

- 人类是否需要在链中？
- 如何检测 LLM Judge 的偏差漂移？
- 沙箱环境如何模拟真实用户旅程？

## 与现有实践对比

| 传统 QA | Agent-as-Judge |
|---------|----------------|
| 人工代码审查 | LLM 自动评估 |
| 固定测试用例 | 动态用户旅程重放 |
| 二元通过/失败 | 置信度评分 |

## 适用场景

- 智能体生成代码的质量保证
- 高频 PR 的自动化审查
- 需要快速反馈的敏捷团队
