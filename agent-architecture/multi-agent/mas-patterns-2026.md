## 为什么需要多智能体

单智能体的局限：
1. 长周期推理能力不足
2. 多步规划和执行困难
3. 大规模工具编排复杂
4. 缺乏自我纠正和验证

多智能体的优势：
1. **专业化胜过通用化** - 每个智能体精通窄任务
2. **并行执行加速** - 30 分钟 → 5 分钟
3. **更好的故障处理** - 单点失败不会导致系统崩溃

## 核心架构模式

### 1. Sequential Pipeline（顺序流水线）
```
Agent A → Agent B → Agent C
```
- 输出作为下一个输入
- 适用：清晰交接的直接工作流

### 2. Coordinator/Dispatcher（协调器/分发器）
```
        ┌→ Specialist A
Coordinator → Specialist B
        └→ Specialist C
```
- 一个智能体接收请求并路由到专家
- 适用：分诊系统、客服路由

### 3. Parallel Processing（并行处理）
```
     ┌→ Agent A ─┐
Task ─→ Agent B ─→ Merge
     └→ Agent C ─┘
```
- 多个智能体同时处理不同部分
- 适用：速度优先且任务独立

## 角色设计模式

企业级多智能体系统的典型角色：

| 角色 | 职责 |
|------|------|
| **Planner** | 分解目标、制定计划 |
| **Executor** | 执行具体任务 |
| **Verifier** | 验证结果正确性 |
| **Optimizer** | 优化性能和成本 |
| **Critic** | 挑战假设、发现问题 |

## 关键成功因素

### 1. 通信与协调
- 结构化消息传递
- 共享状态管理
- 反馈循环

### 2. 记忆架构
- 短期：当前任务上下文
- 长期：跨会话知识
- 共享：智能体间状态

### 3. 安全与治理
- 最小权限设计
- 健壮日志
- 循环预防
- 人在回路控制

## 实践建议

1. **明确目标** - "30 秒内路由客户咨询并提供初步排障步骤" 而非 "自动化客服"
2. **识别任务边界** - 每个需要不同专业知识的任务 = 一个智能体候选
3. **选择合适架构** - 根据工作流特点选择模式
4. **从小开始** - 2-3 个智能体验证，再扩展
