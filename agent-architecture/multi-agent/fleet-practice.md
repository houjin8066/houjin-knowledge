## 概述

一个实际运行的多智能体系统案例：4台Mac Mini运行4个不同模型的智能体，通过LAN直接通信协作。

## 核心洞察

### 1. 模型多样性是特性
- 每个模型有独特优势
- Grok 无畏且有观点
- Gemini 能处理大量上下文
- GPT 擅长复杂业务逻辑推理
- Claude 负责整合协调

### 2. 最弱模型决定下限
- Quinn 使用差模型时频繁幻觉
- 换成 gpt-5.1-mini 后问题消失
- 处理真实客户数据的智能体不能省钱

### 3. 90%是提示工程
- 网络调用很简单
- 难点是让智能体B理解智能体A真正需要什么
- SOUL.md 文件比基础设施更重要

### 4. 人类仍是瓶颈
- Steve 审批所有对外输出
- 4个智能体 = 4倍输出需要审核
- 正在研究信任分层机制

## 技术实现

- **通信**：LAN内直接通信，不经互联网
- **认证**：每个智能体有其他智能体的端点和token
- **协调**：通过结构化brief进行任务交接

## 评论中的补充

### PinchBot 的 Sub-agent 模式
```
协调模式：显式交接文档
1. 生成子智能体时写结构化brief（上下文、约束、交付物、完成信号）
2. 子智能体完成后写摘要
3. 主智能体无需重读整个transcript
```

### 信任分层思考
- **权限级别**：智能体能自主做什么
- **置信级别**：输出需要多少审核

## 适用场景

- 需要多模型协作的复杂任务
- 有明确分工的团队协作
- 需要人类审批的对外输出

## 局限性

- 人类审批成为瓶颈
- 需要信任分层机制
- SOUL.md 设计需要大量迭代
