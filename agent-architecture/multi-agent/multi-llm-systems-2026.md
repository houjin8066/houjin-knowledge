## 核心架构

### Graph-of-Agents (GoA) 框架

2026 年引入的结构化多 agent 管理方法：

```
1. 节点采样 → 选择相关 agent（基于领域专长）
2. 边构建 → 连接可互相增强的 agent
3. 消息传递 → 正向 + 反向传递优化响应
```

**性能**: MMLU-Pro 基准 89.4% 准确率（仅用 3 个 agent vs 全部 6 个）

### 通信协议

| 协议 | 用途 | 特点 |
|------|------|------|
| ACP | 标准化消息 | 跨平台/语言，工作流编排 |
| MCP 2.1 | 工具访问 | 权限验证，实时数据，安全 API |
| A2A | 无监督协作 | 跨功能流程，90% 完成率 |

### 多 LLM 集成

**为什么要多 LLM？**
- 不同模型有不同专长
- 专业化分工提升准确率
- 分布式负载处理复杂任务

**实际效果**:
- ChatDev：错误率降低 40%
- MetaGPT (LLM-A + LLM-B)：92% vs 73%（单 LLM）

## Agent 角色设计

### 典型角色分工

```
需求分析师 → 解读用户需求
代码生成器 → 编写代码（限制工具权限）
测试 Agent → 发现 bug
部署管理器 → 确保正确部署
```

**关键**: 明确角色定义可降低 35% 任务失败率

### 工具权限控制

每个 agent 应该有明确的工具使用权限：
- 代码生成器只能用 MCP 兼容工具
- 提升安全性和效率

## 关键洞察

1. **结构化优于全连接**: GoA 用 3 个 agent 超越 6 个全连接
2. **协议标准化**: MCP/ACP/A2A 是企业部署必备
3. **专业化分工**: 多 LLM 协作 > 单一强模型
4. **权限最小化**: 每个 agent 只给必要的工具权限
