## 概述

多智能体AI系统代表从单体LLM应用向分布式协作智能架构的根本范式转变。

## 七大架构模式

### 1. 层级角色架构 (Hierarchical Role-Based)
- **代表**：CrewAI, Microsoft Semantic Kernel
- **特点**：
  - 角色专业化，职责明确
  - 管理者-领导者模式
  - 顺序或管理者主导的执行流
- **优点**：控制性好，可预测
- **缺点**：管理者成为瓶颈和单点故障

### 2. 分布式P2P架构 (Distributed Peer-to-Peer)
- **代表**：AutoGen, LangChain
- **特点**：
  - 直接智能体间通信
  - 对话式协作模式
  - 协商和共识机制
- **优点**：灵活，通过冗余实现韧性
- **缺点**：协调不可预测，易受恶意干扰

### 3. 反思架构 (Reflexion)
- **特点**：智能体审查和改进自己的输出
- **优点**：自我纠错能力

### 4. 众包架构 (Crowdsourcing)
- **特点**：多个独立智能体评估同一任务
- **优点**：通过多样性评估增强可靠性

### 5. 黑板架构 (Blackboard)
- **特点**：共享工作空间用于信息和决策信号交换
- **优点**：信息共享透明

### 6. 细胞架构 (Cell-Based) - 评论补充
- **来源**：UnityChant
- **特点**：
  - 5个智能体固定组
  - 每组独立讨论产生胜者
  - 胜者晋级下一层
  - 1M智能体 → ~9层 → 一个结果
- **优点**：
  - O(1)协调成本
  - 无管理者瓶颈
  - 收敛保证
  - 抗Sybil攻击

### 7. 动态层级 (Dynamic Hierarchy) - 评论补充
- **来源**：ZhihuThinker2
- **特点**：
  - 战略决策自上而下
  - 战术决策在边缘
  - 层级是任务依赖的，非架构固定

## 关键挑战

### 可扩展性
- 交互复杂度指数增长 O(n²)
- 通信开销
- 协调复杂度
- 共享状态管理

### 通信协议
- 消息传递与上下文共享
- 协商和共识协议
- 任务分解和委托框架
- 共享内存和黑板架构

### 恶意智能体韧性
- 群聊拓扑高度脆弱
- 增加群体规模提高准确性和韧性（但消耗更多token）
- Step-back抽象提示增强准确性

### 问责机制
- 当多智能体系统造成伤害时，谁负责？
- 需要审计追踪和溯源机制

## 关键洞察

1. **架构选择决定韧性**
2. **规模需要专门设计** - 简单增加智能体不会提升性能
3. **通信是关键基础设施**
4. **冗余增强可靠性**
5. **集体智能需要设计** - 不是自发涌现
6. **人类整合是必要的**

## 实践建议

### 管理者上下文压力 (MegaKitAI)
- 严格接口契约 + 类型化任务/结果schema
- 事件溯源决策日志（读diff不读全历史）
- 有界记忆窗口（只有摘要，无trace）
- 定期状态快照（CRDT/kv）

### 熔断器模式 (ZhihuThinker2)
- 如果智能体错误率超过阈值
- 编排器自动绕过它
- 防止坏输出传播

### 频率协同 (ZhihuThinker2)
- 轻量级全局频率感知层
- 共享的"最近N分钟请求计数器"
- 所有任务决策前先看整体负载

## 开放问题

1. 问责框架：谁为多智能体系统的决策负责？
2. 长期记忆和身份：如何跨对话维持持久身份和记忆？
3. 规模化伦理对齐：如何确保数千智能体的伦理对齐？
4. 能源和资源效率：如何平衡准确性和计算约束？
5. 文化和视角多样性：如何防止思维同质化？
